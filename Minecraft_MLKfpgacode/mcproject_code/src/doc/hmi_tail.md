# 按键 / 文字层 / 尾巴 / 霍尔 / 行为层 说明

三个按键、屏幕中间状态带里的 6 行文字（像 OLED 一样显示英文和数字）、步进电机尾巴（UART 只发不收：上电自动回零 + 喂食时左右摇摆）、霍尔传感器（喂食检测）和行为层（喂食时摇尾巴 + 放进食音效）。**接线见 [`pinout.md`](pinout.md)**；音频见 [`audio.md`](audio.md)；屏幕版面见 [`video_pipeline.md`](video_pipeline.md) §4。轮子的控制不在 FPGA 里（放在另一块单片机上）。
状态：每个模块都有测试台，仿真通过；TD 完整流程通过。上板：按键、文字正常；霍尔正常（2026-10-06：3.3 V 供电，**磁铁靠近输出低电平**，已改成低有效）；尾巴正常（2026-10-23）；**2026-10-25 用户不用尾巴了，`mctop.v` 里的尾巴整段注释掉（文件、测试台 `tb_tail` 还在），屏幕上 `TAIL` 那一格也注释掉了**。2026-10-24：重新接线后 `HALL` 一直是 0、模块的灯接上 FPGA 就不亮 → 见 §3 末尾"霍尔一直是 0"。

## 1. 架构

```
SW1 SW2 SW3 ─► mc_key ──短按脉冲──► mc_bench（SW2/SW3 短按 → 相机亮度键）
 (R10 N2 J14)   10 ms 扫描
   mc_osd_dash（把状态排成 3 行文字）──写总线──► mc_disp_if 里的 mc_mixer → mc_osd_text → 屏幕中间状态带

霍尔传感器 ─► mc_hall（同步 + 去抖 20 ms）─ 喂食 = 1 ─► mc_behavior（行为层）─ 摇尾巴脉冲 ─► mc_tail ─UART 115200（只发）─► ZDT X42S 步进驱动器 → 尾巴
 (CEP 脚 17)                                                  └ 音效命令（2.wav）──────► mc_audio
```

行为层 `mc_behavior`（以后避障、跟随的状态机也放在这一层）现在做两件事：**喂食（霍尔 = 1）时**，① 尾巴摇一个来回（约 0.6 秒），摇完检查一次，磁铁还在就再摇一个来回，拿开以后把当前这个来回摇完就停；② 进食音效播一遍（播放中不重复触发，磁铁不拿开也不重播，拿开再靠近才再播）。**狗叫**（10-30 接上）：STM32 的线通着（`I_uwb_link`）并且收不到 UWB 或者距离 ≥ `BARK_CM`（999 = 10 m 以上），连续 `BARK_MS`（1 秒）；或者跟随决策困住了（`I_stuck`，转一圈没有出口，马上叫）→ 播 `3.wav`，条件一直在就循环叫。线不通（STM32 没开）不叫，UWB 偶尔跳一帧不叫。预留了 `I_near`（以后 UWB 距离 < 5 m 时也这样摇尾巴），现在顶层接 0。

- **没有"函数调用"，只有模块 + 端口**：每个模块是一块一直在运行的硬件，状态机"调用"它 = 给它的输入端口一个命令（电平或脉冲），再看它的输出端口（busy / 读数）。见 §5。
- 所有模块跑在 100 MHz 系统时钟域，用 `mc_tick` 的 1 ms / 10 ms / 100 ms 脉冲做节拍（按键 10 ms 扫描、尾巴按 1 ms 计时、屏幕文字 100 ms 刷新）。

## 3. 尾巴：上电回零，以及上次上板尾巴为什么没动

**2026-10-25：尾巴不用了，代码注释掉了**（恢复步骤写在 `mctop.v` 第 4 节开头）。下面的内容留着备查。

**2026-10-21**：用户用 STM32 工程（`Minecraft_MCU/MinecraftDog_STM32/HARDWARE/STEPPER`）测过，驱动器能正常动。FPGA `mc_stepper_emm` 发的每一帧和 STM32 的 `stepper.c` 逐字节一样（使能 / 位置 / 单圈就近回零 / 设零点 / 解除保护都对照过），动作参数也改成和 STM32 `tail.h` 一样（45°、10 RPM、两头停 50 ms、中间停 500 ms、命令间隔 20 ms）。**尾巴最后归 FPGA**：驱动器的 R/A/H 改接 CEP 脚 15，STM32 的 PA9 不再接驱动器（两个只能接一个）。

**上电回零是怎么做的**：驱动器的"坐标零点"= 它上电那一刻的位置，所以以前发"回到绝对位置 0"等于原地不动（上次上板"上电没归位"就是这个原因）。现在改用驱动器自己的**单圈就近回零**（手册 5.4.2，`01 9A 00 00 6B`）：驱动器带单圈绝对编码器，会转到它存的"回零零点"，最多转半圈；FPGA 等 2 秒（`TAIL_HOME_MS`）再发"设坐标零点"（`01 0A 6D 6B`），之后摇摆的"绝对位置 0"就是正中。上电（和 SW1 按住 2 秒整机复位）后 1 秒（`TAIL_INIT_MS`）自动做一遍。

**回零零点要先在驱动器上设一次**（掉电不丢）：先拔掉 FPGA 到驱动器 R/A/H 的那根线 → 驱动器断电 → 用手把尾巴拧到正中 → 驱动器上电 → 驱动器菜单 `0_Set` → `Set 0` → 插回线。

**霍尔 = 1 时尾巴也没动，最可能是串口没通**（FPGA 发出去驱动器没收到）。逐条查：
1. 线：FPGA 的 CEP **脚 15**（E17）接驱动器的 **R/A/H** 脚（不是 T/B/L）；驱动器的 **Gnd 接 CEP 脚 2**。不共地串口收不到。
2. 驱动器必须是**串口 TTL 版本**（RS485 版本的 R/A/H 是差分电平）。
3. 驱动器菜单（出厂值）：`FWType = FW_Emm`（小屏第二行显示 `0.00err` 就是 Emm 固件）、`P_Serial = UART_FUN`、`UartBaud = 115200`、`ID_Addr = 1`、`Checksum = 0x6B`。
4. 驱动器电源 10~29 V 要接着（只插 FPGA 那根线它不会动）；小屏有显示、没报 `Clogging Protect`（堵转保护，FPGA 上电会先发解除保护）。
5. 确认霍尔真的到了 FPGA：屏幕中间第 1 行 `HALL 1`；看不到屏幕时，喂食时右喇叭会放 2.wav（音效和尾巴是同一个触发）。
6. 还不动：用 USB 转 TTL 模块接驱动器，在串口助手里手动发 `01 F3 AB 01 00 6B`（使能）、`01 FD 01 00 0A 00 00 00 01 90 01 00 6B`（10 RPM 转到左 45°），驱动器动了说明驱动器没问题、问题在 FPGA 这一侧的线。

**霍尔一直是 0（模块的灯不接 FPGA 时正常，一接上就一直不亮）**：模块上的灯接在 VCC 和 D0 之间，D0 被拉低灯才亮（磁铁靠近）。接上 FPGA 灯就不亮 = D0 被一个**输出脚**推成了高电平（FPGA 输入脚只有弱上拉，模块一拉就低，不会这样）。最可能是 D0 接到了脚 15（尾巴的串口输出，平时是高）或脚 3（给 STM32 的串口输出），而屏幕的 `HALL` 读的是脚 17（没接东西 = 上拉 = 0）。改接：D0 → CEP **脚 17**，VCC → 脚 1（3.3 V），GND → 脚 2。自己查：断电，D0 那根线先不接，上电后拿一根线把脚 17 碰一下脚 2（GND），屏幕 `HALL` 应该变 1，松开变 0；这样说明 FPGA 这边没问题，再把 D0 接到脚 17。

### 4.1 LED 的含义（没有屏幕、或屏幕不亮时）

| LED | 现象 | 含义 |
| --- | --- | --- |
| LED1 | 约 1 Hz 闪 | PLL 锁定、节拍正常（FPGA 在正常跑）。不闪 = 没配置好 / 时钟没起来 |
| LED2 | 灭 | DDR2 还没校准完（或校准失败） |
| | 约 2 Hz 闪 | DDR2 校准好了，屏幕初始化脚本还没发完 |
| | **常亮** | DDR2 校准好 + 屏幕初始化脚本发完。**没接屏幕也会常亮**（脚本只往屏幕写、不等应答） |
| LED3 | 灭 | 相机寄存器还没配完 |
| | 约 2 Hz 闪 | 相机寄存器配完了，但没有图像帧进来（**没接相机就是这样**） |
| | 常亮 | 图像帧持续进入帧缓存（相机、MIPI、ISP 都正常） |

### 4.2 上电以后应该看到什么

1. LED1 闪；约 0.3 s 后屏幕背光亮、状态方块和文字出现；LED2 常亮。接了相机：LED3 常亮，屏幕上半部分出现实时画面。
2. 约 1 秒：尾巴自己转到回零零点（正中）；屏幕 `TAIL HOME` 约 2 秒后回到 `IDLE`。
3. 约 1 秒：左喇叭（J12）开始放 1.wav，循环。
4. 磁铁靠近霍尔：`HALL 1`，尾巴摇一个来回（磁铁还在就继续摇），右喇叭（J11）放一遍 2.wav。

## 5. 在状态机里怎么"调用"（接口速查）

Verilog 里没有函数调用。对应关系：**函数 = 模块；调用 = 给输入端口赋值；参数 = 输入端口或 parameter；返回值 = 输出端口；`delay_ms` 阻塞 = 状态机里数 tick**。

| 模块 | 输入（你给） | 输出（你读） |
| --- | --- | --- |
| `mc_key` | `I_key[2:0]`（引脚）、`I_tick`（10 ms） | `O_short[i]` 短按脉冲、`O_long[i]` 长按脉冲、`O_pressed[i]` 按着中、`O_down[i]` 按下确认脉冲 |
| `mc_tail` | `I_cmd_wag` 脉冲（空闲且回零做完才收） | `O_busy`、`O_seq`（0 空闲 1 回零 2 摇摆） |
| `mc_audio` | `I_sfx_play` + `I_sfx_clip`（1~64）脉冲 | `O_ready`、`O_bgm_state` / `O_sfx_state`（0 空闲 1 打开中 2 播放中 3 出错）、`O_sfx_busy` 等（`audio.md` §5） |
| `mc_hall` | `I_hall`（引脚）、`I_tick_1ms` | `O_fed`（1 = 磁铁靠近，已去抖） |
| `mc_behavior` | `I_hall`（喂食）、`I_uwb_link` / `I_uwb_ok` / `I_uwb_cm`（`mc_m0_link`）、`I_stuck`（`mc_follow`）、`I_tick_1ms`、`I_near`（预留）；`I_audio_ready` `I_sfx_busy` `I_sfx_state` `I_tail_busy`（反馈） | `O_tail_wag`（接 `mc_tail`）、`O_sfx_play` + `O_sfx_clip`（接 `mc_audio`） |
| `mc_bench` | `I_key_short`、`I_tick_10ms` | `O_cam_key_n`（相机亮度键） |
| `mc_osd_dash` | 各种状态量、`I_tick_1ms` `I_tick_100ms` | 写总线 `O_bus`（接 `mc_osd_text`） |

屏幕加一项显示：改 `tools/gen_osd_dash.pl` 里的 `@ITEMS`（一行 = 一个项目：固定字符串 / 状态名 / 数字，写明行、列、位数），要显示新的信号就在 `@SRC`（数字）或 `%SELID`（状态名）里加取值来源，并给 `mc_osd_dash` 加一个输入端口，然后 `perl tools/gen_osd_dash.pl > mcproject_code/src/rtl/video/osd/mc_osd_dash.v` 重新生成。

## 8. 已知限制 / 上板要验证的

- **尾巴回零**：回零命令和设零点命令的字节按手册第 5 章逐字节核对过；"回零走完"是**定时**的（等 `TAIL_HOME_MS` 2 秒），不读驱动器的回零完成应答（串口只发不收）。驱动器的回零转速改得很慢（菜单 `0_Vel`）的话要把 `TAIL_HOME_MS` 加大。
- 摇摆也是**定时**的（每段等"走完时间 + 停顿"，走完时间按摆幅和转速算），不等驱动器"到位"应答。停顿太短、电机还没走到时下一条命令就来了，会提前掉头（摆幅变小），那就把 `TAIL_SIDE_MS` 加大。
- 驱动器上电比 FPGA 晚超过 1 秒（`TAIL_INIT_MS`）的话，回零命令发出去时它还没准备好：先给驱动器上电，或者上电后 SW1 按住 2 秒整机复位再回零一次。
- SW1 按住 2 秒整机复位，状态机里不要用"SW1 按住超过 2 秒"表示别的操作。
- 文字区的 RAM 在 100 MHz 域写、像素时钟读，没有握手：某个字符恰好在被写的那一刻被读到，那一帧会显示旧值/乱码，下一帧恢复。
