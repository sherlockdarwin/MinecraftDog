2026-10-06 加了**避障**（白平衡后并联一路 160×90 小图 → 地面 / 障碍 → 方向，处理画面放在屏幕下半部分），见 [`obstacle.md`](obstacle.md)，**未上板**。

## 1. 架构

```
 CSI 口 ◄── IMX415                                                          DSI 口 ──► 10.1" 屏
   │ I2C / INCK / RST                                                        ▲ MIPI 4lane    ▲ 背光 / 复位
   ▼                                                                         │               │
┌─────── mc_cam_if 摄像头接口（时钟 = MIPI RX 字节时钟 111.4 MHz）─────────┐ ┌──── mc_disp_if 显示接口（时钟 = DSI 字节时钟 68.49 MHz）────┐
│ mc_cam_pwrup → uicfgimx415(I2C) ◄ mc_ae(自动曝光：曝光 + 增益)           │ │ mc_panel_ctrl → display_config_wrapper(ROM: ILI9881C 初始化)  │
│ D-PHY RX → csi_unpacket_4lane → raw10_unpacket_4lane                     │ │ video_tpg(时序) → mc_mixer(画布版面：相机窗口/状态方块/文字层)│
│ → mc_crop(取 1920×1080) → mc_gamma(黑电平 + 伽马；平均亮度 → mc_ae)     │ │ → rgb_24b_to_32b → dsi_video_mode_packet → D-PHY TX          │
│ → isp_top(去马赛克 + 白平衡) → mc_scale(缩小 2.4 倍 + 打包 128bit)       │ └──────────▲──────────────────────────▲───────────────────────┘
└────────────────────────────┬─────────────────────────────────────────────┘            │                          │
                             │ 像素流（800×448）                                       读使能 / 像素 │
                             ▼                                                                       │
                     ┌─────────── mc_framebuf 帧缓存（时钟 = DDR 用户时钟 132.8 MHz）─────────────────┴──┐
                     │ video_in ─► mc_to_user_interface ─► DDR2 控制器 ◄── video_out（厂商，顺序读）      │
                     └────────────────────────────────────────────────────────────────────────────────────┘
mctop：PLL（100 / 24 / 52.17 / 10 MHz）· 复位同步 · mc_tick · 状态汇总 → LED + 画面上的 8 个状态方块
```
白平衡的输出另外并联一路给 `mc_obs`（避障，相机像素时钟域，[`obstacle.md`](obstacle.md)），结果经写总线送到 `mc_mixer` 里的 `mc_obs_view`。

**为什么这样排**：
- **完整视场**：传感器（2/2 binning）每帧 1097 行 RAW10、每行 1944 像素，录像区 1920×1080（行 11~1090、列 6~1925）。取 1920×1080 全部进 ISP，再等比缩小 2.4 倍成 800×450，帧缓存要求 宽×高 是 1280 的倍数，留 800×448（底下 2 行丢掉，视场的 0.4%）。镜头视场 H72° / V56°，屏幕上看到的就是全部。
- **伽马**：传感器给的是线性亮度，直接显示"亮的很亮、暗的一片黑"。在 RAW10 上先减黑电平（50）再按 sRGB 曲线查表成 8 位（`tools/gen_gamma.pl` 生成 `mc_gamma_lut.v`），暗部细节比在 8 位上做多 2 位精度。例：原始值 100 以前显示 25，现在 64；200 以前 50，现在 109。
- **自动曝光**（`mc_ae`，24 MHz 域）：`mc_gamma` 统计每帧平均亮度（亮于 200 的像素按 200 算，灯这种小亮点拉不高平均值），目标 112（SW2 / SW3 调亮度档 EV−4~+4，每档 ±16）。暗了先加长曝光（最长约 1 帧 = 16.6 ms），到头再加增益（最多 45 dB）；亮了先减增益，再缩短曝光（最短 4 行）。每次写完寄存器等 3 帧看效果，偏差大的步子大（±0.6 / 1.5 / 3.6 / 7.2 dB），0.94~1.06 之内不动。曝光和增益用 REGHOLD 包住同一帧生效。

## 3. 接线

| 底板连接器 | 接什么 | 排线 |
| --- | --- | --- |
| **CSI**（底板下沿左边那个，丝印 `CSI`） | CAM002 摄像头 | CAM002 随附的 40P 排线 |
| **DSI**（底板下沿右边那个，丝印 `DSI`） | 10.1" 屏 | 屏幕软排线：**标 `MLK` 的一端接底板 DSI 座，标 `LCM` 的一端接屏幕的 40P 座** |

- 断电后插拔；两个座都是后掀式：掀起锁扣 → 排线插到底 → 压回锁扣。CSI 排线蓝色加强片朝上；DSI 排线印 `MLK` / `PCBA` 的一面朝上。**排线要插紧**（第一次上板的花屏有一部分是接触不良）。
- 供电：5V/3A 以上的稳压适配器接 Type-C。**不要热插拔 JTAG。**

## 5. 上板步骤与预期现象

1. 下载 `src/boot/MinecraftDog_FPGA.bit`。
2. LED1 约 1 Hz 闪。约 0.3 s 后屏幕背光亮，出现状态方块和文字（相机没接也会出现）；LED2 常亮。
3. 接了相机：LED3 常亮，屏幕上面出现**完整视场**的实时画面（比以前看到的范围大很多：水平 72°），方块 `[3] [4] [5] [6]` 绿。
4. 亮度：画面上电后约半秒内自己调到合适亮度（文字第 2 行 `EXP` = 曝光行数，最长 2275；第 0 行 `GAIN` = 增益，暗处才会往上加，最多 150）。从亮处转到暗处、或者把灯挡住，半秒左右跟上。整体想更亮 / 更暗：SW2 / SW3 短按（第 1 行 `EV+0` 变成 `EV+1` / `EV-1`，每档目标亮度 ±16）。
5. 白平衡：上电后几帧内颜色逐渐变正（十几帧收敛）。
6. **想先只验证屏幕链路**（不看相机）：`mctop.v` 的 `BG_PATTERN` 改 1，没内容的地方会显示测试图案（马赛克）。

## 7. 显示时序（为什么是这几个数）

- DSI 字节时钟 = 52.17 MHz × (`DPLL_MULTI_RATIO` + 1) / 16 = **68.49 MHz**，每通道 548 Mbps，1 个时钟 = 1 个像素。
- **水平**：有效 800 + HSA 24 + HBP 136 + HFP 160 = 1120。**消隐和厂商例程一字不差**：加密的 DSI 打包核不看 D-PHY 的 `ready`，只靠消隐时间留出空隙。压缩过一次（24/100/76），上板花屏。**不要再压缩水平消隐。**
- **垂直**：有效 1280 + VSA 6 + VBP 15 + VFP 16 = 1317。刷新率 ≈ **46.4 Hz**。相机 60 帧，显示端读"往前数第 2 帧"（4 缓冲），不撕裂。想要 60 Hz：`DPLL_MULTI_RATIO` 改成 26（≈ 59.7 Hz），要上板确认。
- 初始化脚本的 ROM 格式：`01 长度 数据…` = DCS 长包、`02 寄存器 值`、`03 命令`、`04` + 4 字节延时（10 MHz 计数）、`05` 结束。

## 8. 约束：IO 约束和时序约束

- **IO 约束**（`mc_pin.adc`）≈ STM32 CubeMX 里"哪个引脚复用成什么功能"；**时序约束**（`mc_timing.sdc`）≈ 时钟树配置，只是告诉工具每个时钟多快，不改变真实频率。
- TD 里改：Hierarchy 里展开 `constraint_1`，双击 `mc_pin.adc` / `mc_timing.sdc` 直接改文本，保存。输入脚不能写 `DRIVESTRENGTH`。

## 10. 仿真与已知风险

- `tb_isp`：取窗 + 去马赛克 + 白平衡（真实 RTL，RAM 用替身 `sim/stubs/stub_demosaic_rams.v`）。假相机按 IMX415 的排列（偶数行 G B、奇数行 R G）出线性渐变，内部像素的 R / G / B 逐个精确核对，3 帧。改成 BGGR / GBRG / GRBG、取窗起始行改成偶数都 FAIL。厂商去马赛克输出比输入晚 1 行、右移 4 像素（画面第 0 行和最左 4 列是填充，缩小以后约 1 个像素，看不出来）；窗口宽度要 > 52 组，否则厂商 `zhenghe` 从第 2 帧起不出帧开始。
- `tb_gamma`：伽马表 1024 项按公式（实数运算）逐项核对、4 个像素位置都走一遍；延迟 1 拍；统计（限幅边界 199 / 201、上一帧最后一拍紧挨下一帧开始、饱和、空帧）；13 个突变全部抓到。
- `tb_scale`：期望值按"二维加权和"直接算（不是 RTL 的先横后竖 + RAM 累加），逐像素精确核对；小尺寸实例（随机空拍；在一个输出行结束的输入行中间截断一帧，打包器里还有没送出的字节；保留行数卡在相位 4 / 7 之间，真实尺寸卡在相位 7 / 9 之间）+ 真实尺寸 1920×1080 → 800×448 一整帧（358400 像素）。
- `tb_ae`：真实 `uicfgimx415` + `mc_ae` + 记录式 I2C 从机（`sim/models/i2c_rec_slave.v`）；测试台独立写的控制规则模型逐次核对写进传感器的 SHR0 / 增益；I2C 上只许出现完整的"待机重写"和"曝光序列"；专门制造"曝光序列写到一半碰上待机重写"、"待机重写的定时正好落在两条曝光寄存器之间"（原版会从中间打断）、"请求在待机重写中途到来"、"写寄存器期间来的帧"。
- `tb_fb`：帧缓存逐像素核对，含相机高速写的压力用例。`tb_mixer`：屏幕合成器整帧逐像素核对（含避障层的位置、安路 Logo 和文字 / 相机 / 避障 / 方块重叠时的叠放顺序）。`tb_logo`：Logo 层单独核对。`tb_awb`：白平衡逐像素核对，35 个突变检查。避障的测试台见 `obstacle.md` §7。
- 厂商的 MIPI 收发、DDR 控制器、DSI 打包核（加密）没法仿真，只能上板。
- TD 完整流程（2026-10-07，含避障 + 跟随）：slice 79.2%、LUT 73%、DSP 19/40、ERAM 67/108；SWNS +0.101 ns、HWNS +0.020 ns，0 违例。
- 仿真验证不了的：传感器真实的行数（按数据手册是 1097 行，少于 1093 行就出不了帧，看方块 `[5]`）、曝光写入后真实的生效帧、日光灯闪烁、亮度 / 噪点的观感。
