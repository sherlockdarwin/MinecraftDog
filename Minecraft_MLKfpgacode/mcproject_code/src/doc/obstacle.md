# 避障 + 跟随说明

避障用单目"地面外观"法（Ulrich & Nourbakhsh 2000，*Appearance-Based Obstacle Detection with Monocular Color Vision*）：车正前方脚下那一小块当作"地面样本"，画面里颜色和它像的是地面（能走），不像的是障碍。全在 FPGA 里流水线做，不占 DDR。
跟随：STM32 经串口送来主人（UWB 标签）在哪，JY61P 陀螺仪给出车头朝哪，**怎么走全部由 FPGA 决定**（§6），两个轮子的 PWM 再送回 STM32 去驱动电机；STM32 只当传感器 + 电机驱动（比赛规则：主控和算法在 FPGA）。
状态（10-30）：**上车能完成基本跟随**。只判断画面下 1/3（镜头前 49 cm ~ 1.35 m）；距离表按上车实测重算（§1）、转向调快一点（§6），这两样还没上车。上车调试按 §10 的顺序。

## 2. 图像依次做了什么

```
白平衡后的 1920×1080（和缩小显示并联）
 → ① 12×12 求平均 → 160×90 小图                         mc_obs_down
 → ② RGB → 亮度 Y + 色度 Cb / Cr                         mc_obs_class
 → ③ 查"地面模型" → 每格判地面 / 障碍
 → ④ 用车前参考区更新地面模型（每帧）
 → ⑤ 3×3 多数表决去噪                                     mc_obs_morph
 → ⑥ 列扫描：每列最近的障碍                               mc_obs_scan
 → ⑦ 16 个扇区 → 距离（查表）→ 和上一帧取近的
 → ⑧ 相邻扇区合成障碍框（红框）
 → ⑨ 按车宽算 9 个方向各能走多远 → 最远的方向；太近 → STOP
 → 屏幕下半部分（mc_obs_view）+ 文字第 4 行 + 跟随决策（mc_follow）
```

| # | 做什么 | 为什么 |
| --- | --- | --- |
| ① | 每 12×12 个像素平均成一格（四舍五入） | 平均掉噪声和地面纹理；数据量少 144 倍，后面全用小 RAM |
| ② | Y = (R+2G+B)/4，Cb = B−Y，Cr = R−Y（移位加减） | 色度基本不随明暗变，阴影不容易被当成障碍 |
| ③ | 色度量化成 16×16 格、亮度 16 格；这一格的颜色在地面直方图里出现 ≥ 12 次（色度和亮度都要）→ 地面，否则障碍 | "和地面像不像"的判断，不用事先知道地面是什么颜色 |
| ④ | 参考区 = 车正前方最下面 48×8 格（约 49~58 cm，黄框）。每帧：旧直方图留 3/4，加上本帧参考区的计数（色度算上周围 3×3 格、亮度算上 ±`OBS_YSPREAD` 格，现在 2 格 = ±32 级） | 换了地面几帧就学会；有东西短暂挡住参考区不会马上学偏；亮度放宽是为了反光 / 阴影的地板（放宽太多，和地面一样灰的东西就判不出来：10-29 试过 4、3，10-30 回到 2） |
| ⑤ | 3×3 里 ≥ 5 格是障碍才算障碍 | 去掉零星误判点、补上障碍里的小洞 |
| ⑥ | 每列从第 `OBS_ROW_MIN` 行（判断区上沿）往下，找最靠下的一段连续 ≥ 2 格的障碍，记它的上沿、下沿 | 下沿 = 障碍和地面的接触点 = 这一列最近的障碍 |
| ⑦ | 160 列每 10 列一个扇区（约 4.5°）；最近的下沿 → 地面距离（按相机高度、倾角算好的表）；没有障碍 = 255 | 16 个方向各有多远；和上一帧取较小值防闪 |
| ⑧ | 相邻扇区都有障碍、上下范围重叠 → 合成一个框 | 一个障碍画一个框，不是 16 个碎框 |
| ⑨ | **按车宽**：候选方向 = 扇区分界线 4~12（−17° ~ +17°，8 = 正前方）。车沿方向 b 直走扫过一条 **30 cm 宽**的带子（车宽 20 cm + 两边各 5 cm）；扇区 j 的障碍离这条路线横向不到 15 cm 才算挡路（离得越远、偏得越多越不挡：正前方时，旁边第 2 个扇区 96 cm 内才挡，第 3 个扇区 65 cm 内才挡）。方向 b 能走多远 = 挡它的障碍里最近的。取最远的方向（最多算 150 cm，一样远取靠正前方的）；最远的也 < `OBS_D_STOP`（60 cm）→ STOP | 车钻得过去的方向，近处窄缝不会被当成路 |

一帧最后一行进来以后约 0.01 ms 出结果，比真实场景晚约 1 帧（17 ms）。方向只到 ±17°：再往外的近处在镜头视场外看不到，要转更大的弯靠边走边看（或原地转，见 §6）。

## 5. 和 STM32 的通讯

UART 115200 8N1，ASCII，**位数不够前面补 0**。接线：CEP 脚 3（FPGA 发，L15）→ STM32 **PB11**（USART3 RX）；STM32 **PB10**（TX）→ CEP 脚 4（FPGA 收，L16）；GND 接 CEP 脚 2。

| 方向 | 帧 | 什么时候 |
| --- | --- | --- |
| STM32 → FPGA | `$` + `l`/`r`（左 / 右）+ 角度 2 位（00~99°）+ 距离 3 位（000~999 cm）+ `&`，例：`$l12350&` = 左 12°、350 cm；超过 99° 发 99，超过 999 cm 发 999 | 每次 UWB 更新发一帧（至少 300 ms 一帧，否则 FPGA 当作收不到） |
| STM32 → FPGA | `$S&` = 收不到 UWB | 丢了就发 |
| FPGA → STM32 | `#` + 左轮（符号 + 4 位）+ 右轮（符号 + 4 位）+ `*`，例：`#+3000-0500*` = 左轮 +3000、右轮 −500（正 = 向前，就是 `PWM_Control_Car` 的参数，满量程 8000） | 每 20 ms 一帧 |
| FPGA → STM32 | `#S*` = 马上停车 | 同上（停的时候每 20 ms 都发） |

- 符号是加上去的：原来的跟随程序原地转弯时一个轮子要倒转（负数）。`l`/`r`/`S` 大小写都行；格式不对的帧整帧丢掉，下一个 `$` 重新开始。
- STM32 那边（`Minecraft_MCU/MinecraftDog_STM32`，已做好）：有新 UWB 数据发 `$…&`，丢了发 `$S&`（100 ms 一帧）；收到 `#…*` 驱动电机，`#S*` 或 200 ms 没收到完整帧就停车；电机左右对调、正反转在 STM32 里换。
- FPGA 这边**不需要 DMA**：DMA 是单片机里"不用 CPU 搬数据"的办法，FPGA 没有 CPU，接收器是一块硬件电路，100 MHz 下每一位都在中间取样、收到一个字节当拍就处理，不会漏收。STM32 用不用 DMA，线上的波形都一样，只是 DMA 发的时候字节之间没有空闲（这种情况 `tb_m0_link` 专门测过）。
### 陀螺仪 JY61P（维特，`sensor/mc_imu_jy61p.v`）

**用 UART，不用 IIC**：模块自己按固定频率推帧，每帧带校验，FPGA 只要一个接收器（和 STM32 用的同一个）；IIC 要另写一个能读的主机、没有校验、开漏线在电机旁边更怕干扰；UART 还能让 FPGA 上电自己配置模块。

| 项 | 内容 |
| --- | --- |
| 接线 | 模块 VCC → CEP 脚 1（3.3 V）、GND → 脚 2、**TX → 脚 6**（FPGA 收，H13）、**RX → 脚 5**（FPGA 发，H14）。模块平放（元件面朝上），装在车中间 |
| 帧（模块 → FPGA） | 11 字节 `55 TYPE D1L D1H D2L D2H D3L D3H D4L D4H SUM`，SUM = 前 10 字节和的低 8 位；`52` 角速度（D3 = Z，× 2000 / 32768 °/s）、`53` 角度（D3 = 航向角，× 180 / 32768 °）。校验不对整帧丢掉 |
| 上电配置（FPGA → 模块） | 模块出厂 9600、10 Hz。FPGA 等 1.2 s，用 115200 听 0.3 s：没有有效帧 → 用 9600 发 解锁 `FF AA 69 88 B5`、波特率 `FF AA 04 06 00`；再用 115200 发 解锁、只输出角速度 + 角度 `FF AA 02 0C 00`、100 Hz `FF AA 03 09 00`、保存 `FF AA 00 00 00`（存进模块，下次直接 115200，只发后 4 条）。每条之间等 50~200 ms（手册：解锁后 200 ms） |
| 归零 | 配置完，车停稳（\|角速度\| ≤ 3°/s）1 s → 当前航向记为 0；一直不停 5 s 后也归零。SW1 长按复位也会重新归零 |
| 掉线 | 100 ms 没有角度帧或角速度帧 → 跟随停车（`NIMU`），屏幕 `LOST`（线上还有数据）或 `NOLK`（0.3 s 线上一个下降沿都没有）；1 s 一个有效帧都没有 → 重新探测、配置、归零 |
| 方向 | 本工程右转为正。上车先用手把车往右转：屏幕 `YAW` 要变大；变小 = 模块朝下装了，`mc_imu_jy61p` 的 `CCW_POS` 改 0 |

- **屏幕第 5 行是 `UWB NOLK`**（2026-10-23 上板就是这样：STM32 屏幕显示 `FPGA STOP`，说明 FPGA → STM32 是通的）：FPGA 一个字节都没收到，查 STM32 **PB10** → CEP **脚 4** 这一根线：双排针一般奇数脚一排、偶数脚一排，脚 4 在脚 3 的**对面**，不是同一排旁边的脚 5；断电量一下 PB10 到脚 4 通不通。也可以把这根线改接 USB 转 TTL 的 RX，串口助手 115200 应该能看到一串 `$l…&`。
- **屏幕第 6 行 `IMU` 在 `CFG` 和别的状态之间来回跳**（约 1 秒一轮）= FPGA 一直没收到一个有效帧，每轮重新探测、配置一遍。代码和管脚（脚 5 = H14、脚 6 = H13，按板子的 CEP 管脚表核对过）没问题时，看跳的是哪个：
  - `CFG` ↔ `NOLK`：脚 6 上一点动静都没有 → 模块 **TX → 脚 6** 没接上（接到了脚 5 / 别的脚、TX RX 接反、插针松）、模块没电（量 VCC–GND 3.3 V）、没共地。
  - `CFG` ↔ `LOST`：模块在说话，但不是 115200 → FPGA 用 9600 发的"改波特率"没到模块：**脚 5 → 模块 RX** 没接上；或者模块以前被上位机改成了 9600 / 115200 以外的波特率（用 USB 转 TTL + 维特上位机看一下，改回 9600 或 115200 即可）。
  - 最省事的检查：断电，把模块的 TX、RX 两根线对调一下再上电。

## 6. 运行逻辑：每 20 ms 怎么决定走哪（`mc_follow`）

STM32 只做两件事：把三个 UWB 基站合成的「主人在左 / 右多少度、多远」发过来；把收到的两轮 PWM 原样给电机。陀螺仪给出车头朝哪（航向角，上电归零，右转为正）。**怎么走全部在 FPGA 里决定**，每 20 ms 一次。
思路：所有方向都换成**世界方向**（= 陀螺仪的航向角），决策只定一个**目标航向**，再由**角度环**把车头转到目标航向并保持住。以前没有陀螺仪，转向只能按 UWB 角度"打多少方向"，两个电机快慢不一样、UWB 跳动都会让车走歪，要等 UWB 角度变了才修。

**① 主人方向**：主人方向 = 车头 + UWB 角度，每次只跟上 1/3（`FOLLOW_ANGLE_FILTER` = 3，去掉 UWB 抖动），刚收到 / 刚找回时直接用。主人相对车头的角度 a = 主人方向 − 车头：车自己转的时候 a 由陀螺仪马上更新，不用等 UWB。

**② 要不要停**（从上往下，满足一条就停：发 `#S*`，两轮直接归 0）：

| 状态 | 条件 |
| --- | --- |
| `LOST` | 收不到 UWB（STM32 发 `$S&`，或 300 ms 没收到 `$…&`） |
| `NIMU` | 陀螺仪没准备好（收不到、正在配置、还没归零，屏幕第 6 行不是 `OK`） |
| `NCAM` | 100 ms 没有新的避障结果（相机断了，看不见路） |
| `HERE` | 主人在 300 cm 以内（到了） |

**③ 要不要原地转向主人**（`TURN`，条件和 STM32 一样）：|a| > 90° **并且连续保持 0.3 秒**才原地转；转到 |a| < 40° 停止原地转，剩下的交给角度环。原地转 = 两轮一正一反 ±2200。

**④ 往前走，定目标航向**：前进量 = 3000 + (距离 − 300) × 10，最多 5000。再看避障结果：9 个方向（正前方、左右 5° / 10° / 15° / 20°），每个方向按 30 cm 宽的走廊算出"能走多远"（§2 ⑨）。

- **挡路**：正前方能走 < **100 cm**，或者"离主人最近的那个方向"能走 < 100 cm。
- **不挡路 → `GO`**：目标航向 = 主人方向。主人方向和现在的目标差不到 **4°** 就不改目标——车走一段直线，主人偏出 4° 再改一次（不会跟着 UWB 抖动左右摆）。
  例外：**刚绕完障碍的 0.5 秒内保持绕行的航向直走**（`AVD`）——障碍出了视场还在车旁边。
- **挡路 → 选一个绕行方向**：在能走 ≥ 100 cm 的方向里挑**代价最小**的（一个都没有，就在 ≥ 60 cm 的里挑）：
  代价 = 2 × |方向 − 主人角度| + 1 × |方向 − 上次绕行的方向|（VFH+ 的代价函数；"上次方向"让绕到一半不左右换边，它存成世界方向，车转了也对得上）。代价一样挑靠正前方的（左右一样先左）。停车、原地转、`GO` 以后"上次方向"作废。
  - 一个方向都不到 60 cm → **`BLK`** 停。
  - 正前方 < **60 cm** → **`SPIN`** 原地转向选中的方向（±2200）。
  - 否则 → **`AVD`**：目标航向 = 车头 + 选中的方向（同样有 4° 回差）。
- **离障碍近就慢**：前进量不超过 3000 + (前面能走多远 − 60) × 20（"前面" = 正前方和要去的方向里近的那个）。
- **现在看 49 cm ~ 1.35 m**（`OBS_ROW_MIN = 60`、镜头竖直装）：1~1.35 m 的障碍看得见但不算挡路（≥ 100 cm），照样朝主人走；进了 1 m 才绕（`AVD`）；到了画面最下面几行（< 60 cm）就停下原地转（`SPIN`）。比 49 cm 更近的看不到：障碍下沿出了画面以后，扫描找到的最低一段就是画面最下沿，按 49 cm 算（仍然 < 60 → 原地转）；比镜头矮又贴得很近的东西会漏掉。

**⑤ 角度环**（`GO` / `AVD`）：误差 e = 目标航向 − 车头（度）。
转向 = `HEAD_KP` × e + 积分 − `HEAD_KD` × 角速度（°/s）；积分每 20 ms 加 `HEAD_KI` × e × 0.02，**只在 |e| ≤ 10° 时累加**（积分分离），最多 ±400；转向最多 ±800（`GO`）/ ±1200（`AVD`）。

| 项 | 作用 |
| --- | --- |
| P（55 PWM / 度） | 车头偏多少就往回打多少 |
| D（8 PWM / (°/s)） | 直接用陀螺仪的角速度当阻尼：转得越快越往回收，不会冲过头；目标航向跳变时也不会猛打（不是对误差求导） |
| I（20 PWM / (度·秒)） | 补两个电机快慢不一样的差：同样的 PWM 车会一直往一边偏，积分慢慢补上，车头最后正好对准目标——**走直线就靠它** |
| 积分分离 | 大转弯（误差 > 10°）时不积分，转过去不会因为攒了一大把积分冲过头 |

**⑥ 两轮**：前进走斜坡（每 20 ms 最多加 200 / 减 400，起步停车平顺），转向每 20 ms 最多变 600；左 = 前进 + 转向、右 = 前进 − 转向，各限 ±6500；发 `#±左±右*`。原地转 = 前进 0、转向 ±2200。
斜坡只管前进：以前两个轮子各自走斜坡，原地转完一个轮子要从 −2200 每 20 ms 爬 200 回到正转，车会多转几十度（仿真里冲过 60°），角度环管不住。

和 STM32 跟随测试模式（`follow.c`，没有陀螺仪）不再一样：前进量、原地转的条件一样，转向换成了角度环。

仿真（`tb_follow` 闭环段，车的模型按 STL：两轮中心距 13 cm、绕后轴中点转；电机转速没有数据，按满量程 8000 ≈ 0.92 m/s 估 → 两轮差 800 PWM ≈ 40°/s；轮速滞后 60 ms；两轮都 4000 时自己往右偏约 15°/s）：走直线 4~6 秒内车头误差 −0.93° ~ −0.39°；主人往右跳 30°：1 秒转过去，第 3 秒对准主人 ±1° 以内；主人在背后：先原地转，再走，最后对着主人 3° 以内。
10-30 转向调快（回差 5→4°、P 40→55、D 6→8、转向变化率 400→600）：另加 UWB 延迟 60 ms + 每帧随机跳 ±3° / ±5° 比较，主人跳 30° 后对准（3° 以内）从 0.9~2.9 s 缩到 0.6~0.7 s，超调 ≤ 1.7°，主人绕着走时落后从约 8° 降到约 6°；走直线时目标航向不多改（不左右摆），轮速滞后加倍到 120 ms 也一样。回差改 3° 或主人方向平滑改 1/2 时，UWB 跳 ±5° 走直线就会左右改目标，所以没改。电机转速是估的，参数要上车调：

| 现象 | 改什么（现在的值） |
| --- | --- |
| 屏幕 `YAW` 往右转反而变小 | 陀螺仪朝下装了：`mc_imu_jy61p` 的 `CCW_POS` 改 0 |
| 走直线左右摆、来回晃 | 减小 `HEAD_KP`（55）或加大 `HEAD_KD`（8）；跟着 UWB 跳动改目标就加大 `FOLLOW_DEADBAND`（4） |
| 拐弯慢、拐不过去、转向有延迟 | 加大 `HEAD_KP`（同时按比例加 `HEAD_KD`）、`FOLLOW_TURN_SLEW`（600）、`HEAD_TURN_MAX`（800） |
| 转过头再回来 | 加大 `HEAD_KD` |
| 走直线一直偏一点（`TGT` 和 `YAW` 差几度不动） | 加大 `HEAD_KI`（20）；两个电机差得很多就加大 `HEAD_I_MAX`（400） |
| 车头跟着主人小幅度来回改 | 加大 `FOLLOW_DEADBAND`（4）或 `FOLLOW_ANGLE_FILTER`（3） |
| 离障碍很近才开始绕 / 绕得太早 | 加大 / 减小 `AVOID_CM`（100）；远处的东西根本不想管就加大 `OBS_ROW_MIN`（60，§1 的表） |
| 绕不开、擦边 | 加大 `AVOID_TURN_MAX`（1200） |
| 绕过去以后拐回来蹭到 | 加大 `AVOID_HOLD_MS`（500） |
| 绕的时候左右来回换边 | 加大 `AVOID_W_PREV`（1） |
| 不往主人那边绕 | 加大 `AVOID_W_TGT`（2） |
| 离障碍太近才原地转 | 加大 `AVOID_SPIN_CM`（60；最近只看得到 49 cm，别小于 55） |
| 靠近障碍还太快 / 太慢 | 减小 / 加大 `AVOID_KP_OBS`（20） |

## 8. 前提和局限

- 地面大致平、颜色和障碍不一样；**上电时车前参考区必须是空地**（上电第 1 帧模型是空的，全判障碍 → STOP，几帧后正常）。
- 和地面同色的障碍、透明 / 反光的东西判不出来（没做边缘检测，省资源）。
- 距离按"障碍的下沿踩在地上"算：悬空的东西（桌沿）只看它在地上的部分。某个东西在参考区里停留很多帧，会被学成地面。
- 镜头竖直装，**镜头前 49 cm 以内的地面看不到**：比镜头（17 cm）矮、又已经贴到车前的东西会漏掉；高的东西还在画面里，按 49 cm 算。
- 原地转（TURN / SPIN）的时候转向那边相机看不到；车身两侧近处也看不到（绕过去以后先直走 0.5 秒，走廊两边各留 5 cm）。
- 看得到的方向只到 ±17°：主人在 17°~90° 之间时一边走一边慢慢转，那边的障碍要转过来才看得见。
- 陀螺仪是六轴的，航向角靠积分，会慢慢漂（静止约 0.5°，车震动时更多）。跟随不怕漂：主人方向每次都用"现在的车头 + UWB 角度"重新算；只有屏幕上的 `YAW` 绝对值会离开 0。
- 相机装法、车宽和 §1 / gen 脚本不一样，距离和"挡不挡"就不准。
