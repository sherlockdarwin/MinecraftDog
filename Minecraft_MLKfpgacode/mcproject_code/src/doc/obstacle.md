# 避障 + 跟随说明

避障用单目"地面外观"法（Ulrich & Nourbakhsh 2000，*Appearance-Based Obstacle Detection with Monocular Color Vision*）：车正前方脚下那一小块当作"地面样本"，画面里颜色和它像的是地面（能走），不像的是障碍。全在 FPGA 里流水线做，不占 DDR。
跟随：STM32 经串口送来主人（UWB 标签）在哪，**怎么走全部由 FPGA 决定**（§6），两个轮子的 PWM 再送回 STM32 去驱动电机；STM32 只当传感器 + 电机驱动（比赛规则：主控和算法在 FPGA）。
状态：避障画面 2026-10 上板确认（真实地面误判不多）；跟随决策 2026-10-21 按 STM32 上车调好的参数重写，仿真 + TD 通过，**未上车**。

## 2. 图像依次做了什么

```
白平衡后的 1920×1080（和缩小显示并联）
 → ① 12×12 求平均 → 160×90 小图                         mc_obs_down
 → ② RGB → 亮度 Y + 色度 Cb / Cr                         mc_obs_class
 → ③ 查"地面模型" → 每格判地面 / 障碍
 → ④ 用车前参考区更新地面模型（每帧）
 → ⑤ 3×3 多数表决去噪                                     mc_obs_morph
 → ⑥ 列扫描：每列最近的障碍                               mc_obs_scan
 → ⑦ 16 个扇区 → 距离（查表）→ 和上一帧取近的
 → ⑧ 相邻扇区合成障碍框（红框）
 → ⑨ 按车宽算 9 个方向各能走多远 → 最远的方向；太近 → STOP
 → 屏幕下半部分（mc_obs_view）+ 文字第 4 行 + 跟随决策（mc_follow）
```

| # | 做什么 | 为什么 |
| --- | --- | --- |
| ① | 每 12×12 个像素平均成一格（四舍五入） | 平均掉噪声和地面纹理；数据量少 144 倍，后面全用小 RAM |
| ② | Y = (R+2G+B)/4，Cb = B−Y，Cr = R−Y（移位加减） | 色度基本不随明暗变，阴影不容易被当成障碍 |
| ③ | 色度量化成 16×16 格、亮度 16 格；这一格的颜色在地面直方图里出现 ≥ 12 次（色度和亮度都要）→ 地面，否则障碍 | "和地面像不像"的判断，不用事先知道地面是什么颜色 |
| ④ | 参考区 = 车正前方最下面 48×8 格（约 23~26 cm，黄框）。每帧：旧直方图留 3/4，加上本帧参考区的计数（色度算上周围 3×3 格、亮度算上 ±2 格） | 换了地面几帧就学会；有东西短暂挡住参考区不会马上学偏 |
| ⑤ | 3×3 里 ≥ 5 格是障碍才算障碍 | 去掉零星误判点、补上障碍里的小洞 |
| ⑥ | 每列从 1.5 m 线往下，找最靠下的一段连续 ≥ 2 格的障碍，记它的上沿、下沿 | 下沿 = 障碍和地面的接触点 = 这一列最近的障碍 |
| ⑦ | 160 列每 10 列一个扇区（约 4.5°）；最近的下沿 → 地面距离（按相机高度、倾角算好的表）；没有障碍 = 255 | 16 个方向各有多远；和上一帧取较小值防闪 |
| ⑧ | 相邻扇区都有障碍、上下范围重叠 → 合成一个框 | 一个障碍画一个框，不是 16 个碎框 |
| ⑨ | **按车宽**：候选方向 = 扇区分界线 4~12（−19° ~ +19°，8 = 正前方）。车沿方向 b 直走扫过一条 **30 cm 宽**的带子（车宽 20 cm + 两边各 5 cm）；扇区 j 的障碍离这条路线横向不到 15 cm 才算挡路（离得越远、偏得越多越不挡：正前方时，旁边第 2 个扇区 86 cm 内才挡，第 4 个扇区 45 cm 内才挡）。方向 b 能走多远 = 挡它的障碍里最近的。取最远的方向（最多算 150 cm，一样远取靠正前方的）；最远的也 < 35 cm → STOP | 车钻得过去的方向，近处窄缝不会被当成路 |

一帧最后一行进来以后约 0.01 ms 出结果，比真实场景晚约 1 帧（17 ms）。方向只到 ±19°：再往外的近处在镜头视场外看不到，要转更大的弯靠边走边看（或原地转，见 §6）。

## 5. 和 STM32 的通讯

UART 115200 8N1，ASCII，**位数不够前面补 0**。接线：CEP 脚 3（FPGA 发，L15）→ STM32 **PB11**（USART3 RX）；STM32 **PB10**（TX）→ CEP 脚 4（FPGA 收，L16）；GND 接 CEP 脚 2。

| 方向 | 帧 | 什么时候 |
| --- | --- | --- |
| STM32 → FPGA | `$` + `l`/`r`（左 / 右）+ 角度 2 位（00~99°）+ 距离 3 位（000~999 cm）+ `&`，例：`$l12350&` = 左 12°、350 cm；超过 99° 发 99，超过 999 cm 发 999 | 每次 UWB 更新发一帧（至少 300 ms 一帧，否则 FPGA 当作收不到） |
| STM32 → FPGA | `$S&` = 收不到 UWB | 丢了就发 |
| FPGA → STM32 | `#` + 左轮（符号 + 4 位）+ 右轮（符号 + 4 位）+ `*`，例：`#+3000-0500*` = 左轮 +3000、右轮 −500（正 = 向前，就是 `PWM_Control_Car` 的参数，满量程 8000） | 每 20 ms 一帧 |
| FPGA → STM32 | `#S*` = 马上停车 | 同上（停的时候每 20 ms 都发） |

- 符号是加上去的：原来的跟随程序原地转弯时一个轮子要倒转（负数）。`l`/`r`/`S` 大小写都行；格式不对的帧整帧丢掉，下一个 `$` 重新开始。
- STM32 那边（`Minecraft_MCU/MinecraftDog_STM32`，已做好）：有新 UWB 数据发 `$…&`，丢了发 `$S&`（100 ms 一帧）；收到 `#…*` 驱动电机，`#S*` 或 200 ms 没收到完整帧就停车；电机左右对调、正反转在 STM32 里换。
- FPGA 这边**不需要 DMA**：DMA 是单片机里"不用 CPU 搬数据"的办法，FPGA 没有 CPU，接收器是一块硬件电路，100 MHz 下每一位都在中间取样、收到一个字节当拍就处理，不会漏收。STM32 用不用 DMA，线上的波形都一样，只是 DMA 发的时候字节之间没有空闲（这种情况 `tb_m0_link` 专门测过）。
- **屏幕第 5 行是 `UWB NOLK`**（2026-10-23 上板就是这样：STM32 屏幕显示 `FPGA STOP`，说明 FPGA → STM32 是通的）：FPGA 一个字节都没收到，查 STM32 **PB10** → CEP **脚 4** 这一根线：双排针一般奇数脚一排、偶数脚一排，脚 4 在脚 3 的**对面**，不是同一排旁边的脚 5；断电量一下 PB10 到脚 4 通不通。也可以把这根线改接 USB 转 TTL 的 RX，串口助手 115200 应该能看到一串 `$l…&`。

## 6. 运行逻辑：每 20 ms 怎么决定走哪（`mc_follow`）

STM32 只做两件事：把三个 UWB 基站合成的「主人在左 / 右多少度、多远」发过来；把收到的两轮 PWM 原样给电机。**怎么走全部在 FPGA 里决定**，每 20 ms 一次，按下面的顺序：

**① 角度平滑**（和 STM32 `follow.c` 一样）：每次只跟上新角度的 1/3（去掉 UWB 抖动）；刚收到 / 刚找回主人时直接用新角度。下面的"主人角度 a"都是平滑后的。

**② 要不要停**（从上往下，满足一条就停：发 `#S*`，两轮直接归 0）：

| 状态 | 条件 |
| --- | --- |
| `LOST` | 收不到 UWB（STM32 发 `$S&`，或 300 ms 没收到 `$…&`） |
| `NCAM` | 100 ms 没有新的避障结果（相机断了，看不见路） |
| `HERE` | 主人在 300 cm 以内（到了） |

**③ 要不要原地转向主人**（`TURN`，和 STM32 一样）：|a| > 90°（主人在侧面 / 后面）**并且连续保持 0.3 秒**才原地转（UWB 角度跳一下不算）；一直转到 |a| < 40° 才停止原地转。原地转 = 两轮一正一反 ±2200，转向主人那边。

**④ 往前走**：前进量 = 3000 + (距离 − 300) × 10，最多 5000（和 STM32 一样）。然后看避障结果：9 个方向（正前方、左右 5° / 10° / 15° / 19°），每个方向按 30 cm 宽的走廊算出"能走多远"（§2 ⑨，1.5 m 内没有障碍 = 不限）。

- **挡路**的意思：正前方能走 < **100 cm**，或者"离主人最近的那个方向"能走 < 100 cm（主人在 19° 外就是最边上的 19°）。
- **不挡路 → `GO`**：对着主人走，转向和 STM32 一样（±5° 以内不拐；超出的部分每 1° 转前进量的 0.3%，最多 9%；每 20 ms 最多变 12）。
  例外：**刚绕完障碍的 0.5 秒内先直走**（屏幕显示 `AVD`）——绕过去的障碍已经出了视场，但还在车旁边，马上拐回去会蹭到。
- **挡路 → 选一个绕行方向**：在能走 ≥ 100 cm 的方向里挑**代价最小**的（一个都没有，就在能走 ≥ 60 cm 的方向里挑）：
  代价 = 2 × |方向 − 主人角度| + 1 × |方向 − 上次绕行的方向|。
  主人那一项权重大 → 往离主人近的那边绕；"上次方向"那一项 → 绕到一半不会左右来回换边（VFH+ 的代价函数、改进 Follow-the-Gap 的"换边惩罚"都是这个思路）。代价一样就挑靠正前方的（左右一样先挑左）。停车、原地转向主人、正常跟随（`GO`）以后，"上次绕行的方向"作废。
  - 一个方向都不到 60 cm → **`BLK`** 停。
  - 正前方 < **45 cm**（太近了，再往前会撞）→ **`SPIN`** 原地转向选中的方向（±2200）。
  - 否则 → **`AVD`** 一边走一边转向选中的方向；转向用"绕行系数"（比跟随猛，绕得开）：每 1° 转前进量的 1.2%，最多 30%，每 20 ms 最多变 40。
- **离障碍近就慢**：前进量不超过 3000 + (前面能走多远 − 60) × 20（"前面" = 正前方和要去的方向里近的那个；1.5 m 内都没有障碍就不限）。

**⑤ 两轮**：左 = 前进 + 转向、右 = 前进 − 转向，各限 ±6500；斜坡：每 20 ms 最多加 200 / 减 400（和 STM32 一样）；发 `#±左±右*`。

**没有障碍时，FPGA 的计算和 STM32 跟随测试模式一模一样**（同样的整数运算、同样的参数，`tb_follow` 用照搬 `follow.c` 的模型逐个核对；两边取 UWB 数据的时刻不同，车上看到的数会差一点）。所以可以先在同一个地方试 STM32 模式，再试 FPGA 模式，对着屏幕上的两轮命令看。

参数在 `mctop.v` 配置区：`FOLLOW_*` = STM32 `follow.h` 的值；`AVOID_*` = 避障（**还没上车调**）：

| 现象 | 改什么（现在的值） |
| --- | --- |
| 离障碍很近才开始绕 / 绕得太早 | 加大 / 减小 `AVOID_CM`（100） |
| 绕不开、擦边 | 加大 `AVOID_TURN_PER10K`（120 = 1.2%/°）、`AVOID_TURN_MAX`（3000 = 30%）、`AVOID_TURN_STEP`（40） |
| 绕过去以后拐回来蹭到 | 加大 `AVOID_HOLD_MS`（500） |
| 绕的时候左右来回换边 | 加大 `AVOID_W_PREV`（1） |
| 不往主人那边绕 | 加大 `AVOID_W_TGT`（2） |
| 离障碍太近才原地转 | 加大 `AVOID_SPIN_CM`（45） |
| 靠近障碍还太快 / 太慢 | 减小 / 加大 `AVOID_KP_OBS`（20） |

## 8. 前提和局限

- 地面大致平、颜色和障碍不一样；**上电时车前参考区必须是空地**（上电第 1 帧模型是空的，全判障碍 → STOP，几帧后正常）。
- 和地面同色的障碍、透明 / 反光的东西判不出来（没做边缘检测，省资源）。
- 距离按"障碍的下沿踩在地上"算：悬空的东西（桌沿）只看它在地上的部分。某个东西在参考区里停留很多帧，会被学成地面。
- 原地转（TURN / SPIN）的时候转向那边相机看不到；车身两侧近处也看不到（绕过去以后先直走 0.5 秒，走廊两边各留 5 cm）。
- 看得到的方向只到 ±19°：主人在 19°~90° 之间时一边走一边慢慢转，那边的障碍要转过来才看得见。
- 相机装法、车宽和 §1 / gen 脚本不一样，距离和"挡不挡"就不准。
