## MinecraftDog STM32F103RCT6

> 初赛定版 (2026-11-02)。一路遇到的问题和解决方案、写技术文档能用的数据见 [`STM32开发记录.md`](STM32开发记录.md)。

机器狗的单片机端 (绿深 STM32F103RCT6 板, 8 MHz 晶振, 72 MHz)。跟随 + 避障决策在 FPGA, STM32 负责:
四个 UWB 基站定位 → 发给 FPGA; 收 FPGA 的两轮 PWM → 驱动电机; 屏幕。尾巴 (步进电机) 归 FPGA。
另有一个**跟随测试模式** (长按 KEY1): 不经过 FPGA, 用 STM32 自己的 `follow.c` 跟着 UWB 走, 用来调跟随算法。

### 硬件

UWB 基站供电: 转接板 (TX RX 5V GND) 上没有稳压芯片, 标 5V 的脚就是模块 VCC (原理图核对过), 规格书 3 ~ 5 V、推荐 3.3 V, 所以接 5 V 或 3.3 V 都行; 数据线 3.3 V; 规格书每个 300 mA, 四个约 1.2 A, 从车上 5 V 降压取电; 必须共地。GPIO 不能给基站供电 (只有 3.3 V、单脚约 25 mA)。

**第四个基站 (后基站) 接线**: 转接板 Pin1 TX → **PA9**, Pin3 5V → 3.3 V 或 5 V, Pin4 GND → GND, Pin2 RX 不接。PA10 不接。
5 V 排针不够时接 TB6612 模块 (D153C) J5 的 3V3 脚, GND 接 J5 的 GND 排 (卖家标 3.3 V 输出 500 mA)。**J5 里可能有 VM 脚 (电池电压, 2S 约 8 V), 接之前先用万用表量, 读数 3.2 ~ 3.4 V 才能接**。
**为什么接 PA9 不接 PA10** (2026-11-01 用 ST-Link 实测): 板子上有东西一直把 PA10 拉高, 拔掉线、内部下拉也读到高, 基站 TX 压不过它, 屏幕 `B` 那一列不涨。大概率是板载 USB 串口芯片, 但没有原理图, 没证实。PA9 只是弱上拉, 基站拉得动, 所以 USART1 用单线模式从 TX 脚 (PA9) 收。实测每秒 40 帧, 校验错 0。

### UWB

- **定位**: 左 / 前 / 右 / 后四个 120° 定向基站, 安装角 -90° / 0° / +90° / 180° (`uwb.h`)。每个基站约 40 帧/秒。
  车体角度**左负右正**, 0 = 正前方, ±180 = 正后方。融合每 20 ms 算一次 (`uwb.c` 的 `UWB_Fuse`)。
- **安装几何**: 左右背靠背, 间距约 10 cm; 前基站在它们靠前边缘的中线上; 后基站在前基站正后方约 36 cm, 背对背。
- **原理**: 基站靠相位差测角, 读数的 sin 是信标方向在它天线轴上的投影, 信标在基站背面也一样, 所以背后的信号会镜像到前面。
  设信标车体角为 θ:

  | 基站 | sin(读数) | 量的是 | 分不清 |
  | ---- | ---- | ---- | ---- |
  | 前 | sin θ | 左右 | θ 和 180° - θ (前后) |
  | 后 | -sin θ | 左右 | 同上 |
  | 左 | cos θ | 前后 | θ 和 -θ (左右) |
  | 右 | -cos θ | 前后 | 同上 |

  以前 3 个基站看不到后方的根本原因: 信标在正后方时前基站读数很小, "选读数最小的基站"就选中它, 当成正前方。现在分三步:

  1. **前后** (`UWB_UpdateFrontRear`): 前后基站距离差 fb = -36 × cos θ, 在 θ 接近 0° / 180° (左右基站到了测角边缘) 时最大;
     θ 接近 ±90° 时距离差没用, 但左右基站读数最准。两个合成一个分数 e (-100 ~ +100, 正 = 前), 超过 ±25 并保持 100 ms 才换前后,
     中间保持。背对信标的基站信号绕着走, 距离只会偏长, 所以这个差值只会更大, 不会反号。
  2. **左右** (`UWB_UpdateSide`): 不再用距离差。听朝着信标的前 / 后基站的正负号: 最近 5 帧全在 ±60° 以内、全部同号算一票, 连续 80 ms 才换边;
     后半圈读数小于 12° (人几乎正后方) 不换, 而且前基站的镜像读数不能反对。其余时候沿用上一次的左右 (人换边只能经过正前 / 正后, 那时读数最准)。
  3. **偏多少度** (`UWB_SelectAnchor`): 朝着信标、读数在 ±60° 以内的基站里, 挑离自己正前方最近的 (换基站有 5° 回差), 用它的读数算。
- **异常值**: 每路取最近 5 帧中值; 角度超 ±90°、距离 0 或超 100 m 的帧不用; 基站之间最多差 36 cm, 所以距离和其余基站差超过 60 cm 的这一拍不用;
  前后距离差限幅 ±60 cm 再平滑; 输出一拍跳 60° 以上先保持, 持续 200 ms 才认。
- **降级**: 单路 200 ms 没有效帧就不参与, 用剩下的 (朝着信标的基站没了就用背对的镜像读数)。

  | 丢了 | 怎么办 |
  | ---- | ---- |
  | 后基站 (或者还没接) | 前后只靠左右基站读数, 正前 / 正后保持; 比以前 3 基站好, 一上电人就在正后方 150° 以外时当成前方 |
  | 前基站 | 后基站镜像读数顶上 |
  | 左 / 右基站 | 另一个的镜像读数顶上; 都丢了用前后基站 |
  | 前 + 后基站 | 不知道左右: 沿用上次的左右, 偏离车头不到 45° 按正前方走, 否则狗会一直往一边转 |
  | 全部 500 ms | `UWB_GetTarget` 报收不到, 和以前一样 `$S&` + 立刻停车 |

- **限制**: 一上电人就站在正侧面 (±60° ~ ±120°) 时前后基站都在测角边缘, 左右只能猜, 猜错了狗先往反方向转, 转到人在 120° 以外读数可信时改过来。
- **发给 FPGA**: 协议不变, 超过 99° 发 99, FPGA 的 `|角度| > 90` 保持 0.3 秒原地转照常工作, 不用改 FPGA。
- **解帧** (`uwb.c`): 4 个 `FF` 帧头, 第 9~10 字节命令码 `0x2001` 就收 37 字节, 校验 = 前 36 字节异或。
  **不检查长度字段和版本号**: 实测基站发的版本是 `0x0102`, 规格书写 `0x0100`, 以前因此一帧都解不出来;
  厂家例程 (`示例代码/STM32F1-Usart`) 也只看帧头 + 命令码。
- **屏幕排查** (中间小字, 1 秒刷一次):

  - `L1480F1480R1480B1480`: 每个基站收到的字节 (后 4 位, 正常每秒涨约 1480)。不涨 = 线没接对 (基站 TX 要接 STM32 RX) 或没共地。
  - `L  -23deg   3.50 m` / `F …` / `R …` / `B …`: 每个基站**自己**最近一帧解出来的角度和距离, 不经过融合。
    角度是基站本地角 (从它自己看: 左负右正, 0 = 它正对的方向; 已经乘过 `UWB_*_ANGLE_SIGN`)。绿字 = 最上面一行用的是这个基站; 灰字 `no data` = 500 ms 没新帧。
  - `fb -36 e +94 FRONT R4` (第 2 行下面): 融合过程。fb = 前基站距离 - 后基站距离 (cm, 平滑后; 空 = 前后基站缺一个); e = 前后分数; 判成 FRONT / REAR; 左 L / 右 R (`?` = 还不知道); 最后一位 = 有数据的基站数。四个都有是绿字, 否则黄字。
  - 解帧排查用的校验错次数、帧头字段不再显示, 要看在 Debug 里调 `UWB_GetStats()`。

### UWB 上车标定 (按顺序, 屏幕 1 秒刷一次, 人站住等两下再看)

信标离车约 3 m, 高度和平时拿着一样。下面读数都是**本地角**, 以"信标在车右边"为例; 信标换到车左边时 F、B 反号, L、R 不变 (左右基站量的是前后)。

| θ (车体角) | L | F | R | B |
| ---- | ---- | ---- | ---- | ---- |
| 右前 30° | +60 (镜像) | +30 | -60 | -30 (镜像) |
| 右侧 90° | 0 (镜像) | +90 | 0 | -90 |
| 右后 150° | -60 (镜像) | +30 (镜像) | +60 | -30 |

1. **接线**: 第一行小字 `B` 那一列每秒涨约 1480, 另外三列也没变慢。四列都变慢 = 4 个基站在分信标的时隙, 看 `B` 那行有没有数据; `B` 一直是 0 看上面"接线"那段, 基站 TX 要接 PA9。
2. **后基站正负号**: 站到右后 150°, `B` 行角度应该是负的; 是正的把 `uwb.h` 的 `UWB_BACK_ANGLE_SIGN` 改成 `+1`。仿真里配反了狗不会抽 (前基站的镜像读数会拦住), 但人绕过正后方换边时换不过来。
3. **前后距离偏差**: 站到正右 90° 记下 `fb`, 再到正左 90° 记下 `fb`, 平均值写进 `UWB_FB_RANGE_BIAS_CM` (比如 +8 就写 8)。写完正前方应该约 -36, 正后方约 +36; 整体偏小把 `UWB_FB_BASELINE_CM` 改成实量的基线 (信标举得高也会偏小: 乘 cos 仰角)。
4. **前后门限**: 站住不动看 `fb` 上下抖多少 (p-p)。`UWB_FR_ENTER_SCORE` = 25 相当于 fb ±9 cm, 抖动 p-p 超过 18 cm 就把它加大到 40, 或者把 `UWB_FB_DIFF_FILTER` 从 4 改成 8 (更稳, 慢一点)。验证: 60° 处 `FRONT` 稳住不动, 120° 处 `REAR` 稳住不动。
5. **可信区间**: 绕车慢慢走一圈, 看 `F` / `B` 读数从多少度开始来回跳, `UWB_ANGLE_TRUST_DEG` 取比它小 10° (默认 60, 就是规格书的 120° 区)。
6. **距离一致性**: 绕车看四个距离, 正常最多差 36 cm 多一点。总差 60 cm 以上时最后一位 (基站数) 不变, 但这路这一拍不用; 经常这样把 `UWB_RANGE_SPREAD_CM` 加大。
7. **正后方**: 站到正后方, 第 1 行不该左右来回跳; 跳就加大 `UWB_SIDE_REAR_DEADBAND_DEG` (12)。
8. **上车跑**: 人走到车后方, 狗应该原地转向人, 不再往前走、不抽。转得慢、人一走就跟丢, 看第 1 行角度滞后: 融合滞后约 100 ms, 可以把 `UWB_MEDIAN_SAMPLES` 从 5 改成 3 (抗干扰差一点)。

| 参数 (`uwb.h`) | 现在 | 怎么来的 |
| ---- | ---- | ---- |
| `UWB_ANGLE_TRUST_DEG` | 60 | 规格书: 120° 内数据更准 |
| `UWB_RANGE_SPREAD_CM` | 60 | 基线 36 + 余量 24 (规格书 ±5 cm, 室内按 ±12 cm, 两个基站之差) |
| `UWB_FB_DIFF_CLAMP_CM` | 60 | 和上一行一样, 真实距离差不会超过 36 |
| `UWB_FR_ENTER_SCORE` | 25 | cos 75° ≈ 0.26: 约 ±75° / ±105° 才换, 这附近左右基站正在用, 判错也不影响角度 |
| `UWB_FR_CONFIRM_MS` | 100 | 比平滑时间常数 (约 70 ms) 长一点 |
| `UWB_SIDE_CONFIRM_MS` | 80 | 约 3 帧, 和以前一样 |
| `UWB_SIDE_REAR_DEADBAND_DEG` | 12 | 测角误差 ±3° 的 4 倍, 人站正后方不翻 |
| `UWB_JUMP_DEG` / `_CONFIRM_MS` | 60 / 200 | 车原地转每 20 ms 才几度, 一拍跳 60° 不可能是真的; 200 ms 内能恢复就当没发生 |
| `UWB_ANCHOR_STALE_MS` | 200 | 约 8 帧没数据才算这路掉线, 比 500 ms 的全丢短 |

### UWB 跟随 (跟随测试模式 `follow.c` / `follow.h`)

**思路** (每 20 ms):

1. 收不到 UWB / 距离 > 20 m / 距离 ≤ 2 m → 停车。
2. 角度平滑: 每次只跟上新角度的 1/3 (约 50 ms), 去掉抖动。
3. 偏超过 90° 并保持 0.3 秒 (人在侧面 / 后面) → 原地转 (两轮 ±2200), 转到 40° 以内再往前走。
4. 否则往前走: 前进 = 3000 + (距离 - 200 cm) × 10, 最多 5000。
   转向按**前进的比例**算 (弯的急缓和车速无关): ±5° 以内不拐; 超出部分每 1° 转前进的 0.4%, 最多 10%;
   转向每 20 ms 最多变 15 (慢慢打方向)。左 = 前进 + 转向, 右 = 前进 - 转向。
5. 两轮各自斜坡: 每 20 ms 最多加 200 / 减 400。

**调参** (`follow.h`):

| 现象                         | 改什么 (现在的值)                                                                               |
| ---------------------------- | ----------------------------------------------------------------------------------------------- |
| 走不动 / 太慢                | 加大 `FOLLOW_START_PWM` (3000)                                                                |
| 原地转不动                   | 加大 `FOLLOW_PIVOT_PWM` (2200)                                                                |
| 左右摆头                     | 加大 `FOLLOW_ANGLE_DEADBAND_DEG` (5) 或 `FOLLOW_ANGLE_FILTER` (3)                           |
| 弯太急 / 转向不灵敏          | 减小 / 加大 `FOLLOW_TURN_MAX_PER10K` (1000 = 10%) 或 `FOLLOW_TURN_PER10K_PER_DEG` (40 = 0.4%) |
| 打方向太猛 / 太慢 (过于谨慎) | 减小 / 加大 `FOLLOW_TURN_STEP_PWM` (15)                                                       |
| 拐不过来、人到侧面跟不上     | 加大 `FOLLOW_TURN_MAX_PER10K`, 或减小 `FOLLOW_PIVOT_ENTER_DEG` (90)                         |
| 突然原地转                   | 加大 `FOLLOW_PIVOT_CONFIRM_MS` (300)                                                          |
| 停车距离                     | `FOLLOW_STOP_DISTANCE_CM` (200)                                                               |

**调参记录** (1 kg 左右的车, 2026-10 上车实测): 起步从 600 (推不动) 加到 3000; 转向从"角度 × 系数"改成前进的比例 + 方向盘限速, 解决拐弯太急、左右摆头; 原地转从 75° 改成 90° 并保持 0.3 秒, 不再突然原地转。10-29 改对 UWB 角度正负号 (以前人在 60° 会被算成 120°); 11-01 加第四个基站后角度能到 ±180, 平滑改走近路, 这一版跟随测试模式没上车重新验证。

### 和 FPGA 的通讯 (USART3, 115200 8N1, ASCII, 位数不够补 0)

| 方向          | 帧                                                                                                                                                     | 含义 / 频率                                                       |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| STM32 → FPGA | `$` + `l`/`r` + 角度 2 位 + 距离 3 位 + `&` | 主人在左 / 右多少度、多远 cm, 如 `$l12350&`; 超过 99° / 999 cm 发 99 / 999; 有新 UWB 数据就发 |
| STM32 → FPGA | `$S&`                                                                                                                                                | 收不到 UWB; 刚丢立刻发, 之后 100 ms 一帧                          |
| FPGA → STM32 | `#` + 左轮 (符号 + 4 位) + 右轮 (符号 + 4 位) + `*`                                                                                                | 两轮 PWM, 正 = 前进, 满量程 8000, 如 `#+3000-0500*`; 20 ms 一帧 |
| FPGA → STM32 | `#S*`                                                                                                                                                | 立即停车                                                          |

- 超时: FPGA 300 ms 收不到 `$…&` 当 UWB 丢; STM32 200 ms 收不到完整 `#…*` 停车。
- 解包: `#` 重新开始一帧, 帧外字节丢掉, 格式不对整帧丢; 结果在 `fpgamlk.c` 顶部的 `g_fpga_*` 变量。

### 步进电机 (尾巴)

### CubeMX / 工程注意

- 不能改掉: USART3_RX DMA = Circular、USART3 中断打开; USART1/2、UART4/5 中断打开 (在 `stm32f1xx_it.c` 的 USER CODE 0
  里直接调 `UWB_IRQHandler()` 后 return); TIM3 Period = 7999; I2C1 Disable; "Keep User Code" 勾上。
- 建议把 PA6 / PA7 钉住 (右键 → Signal Pinning), 否则开别的外设时 CubeMX 可能把电机 PWM 挪走。
- 源码目录: `Core` `Drivers` `ALGORITHM` `HARDWARE` `SYSTEM`; include: `../` `../SYSTEM` `../HARDWARE` `../HARDWARE/MOTOR` `../HARDWARE/UWB`。
  CubeMX 重新生成会删掉"整个根目录当源码"的设置, **新 .c 文件必须放进上面这几个文件夹**。
- 重新生成前关掉编辑器里的 `main.c`, 生成后 F5 刷新, 否则旧内容一保存就盖掉 USER CODE。
