## 2. 问题和解决方案

### 2.1 工程和 CubeMX

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| CubeMX 重新生成后 `bsp_init()` / `Scheduler_Run()` 不见了 | 编辑器里还开着旧的 `main.c`，一保存就把 USER CODE 盖掉 | 生成前关掉 CubeMX 管的文件，生成后在工程上按 F5 |
| 新写的 `.c` 不被编译 | 重新生成会删掉"整个工程根目录当源码"的设置 | 新文件只放进 `Core` `Drivers` `ALGORITHM` `HARDWARE` `SYSTEM`；新文件夹手动加进 Source Location |
| 有几个设置改了不报错，只会静默不工作 | USART3 接收 DMA 不是 Circular 时收满一圈就停；USART3 中断不开时 DMA 发送结束不了；TIM3 周期不是 7999 时 PWM 刻度和 FPGA 对不上 | 全部写进 README 的"不能改掉"清单 |
| 开别的外设时电机 PWM 可能被挪走 | CubeMX 会自动给新外设让路 | PA6 / PA7 用 Signal Pinning 钉住 |

### 2.2 屏幕

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 只接电源和 SCL / SDA，屏幕全白 | 这是 SPI 接口的 ST7735S 彩屏，不是 OLED；背光亮了但没初始化 | 6 根线全接，按 1.44 寸（green tab）初始化；先清黑显存再开背光，开机不闪白 |
| 硬件 SPI 用不了 | SPI1 只有两组脚：默认组的 PA7 是右轮 PWM，重映射组的 PB3 是编码器；板子 LCD 排针的 PB8 / PB9 本来就没有 SPI 功能 | 软件 SPI，1 秒刷一次，每次约 20 ms，放在任务表最后 |
| PB6 / PB7 用不了 | 被 I2C1 占着 | I2C1 设成 Disable |

### 2.3 UWB 收数据

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 收到字节，但一帧都解不出 | 基站实际发的版本号是 `0x0102`，规格书写 `0x0100`（规格书里定位帧和心跳帧的版本本身也对不上） | 和厂家例程一样，只看 4 个 `FF` 帧头、命令码和异或校验，不看长度和版本；用规格书的两个例子帧验证过 |
| 帧头可能对不齐（写解析时考虑到、专门测过的情况） | 上一帧的校验字节正好是 `FF` 时，帧头前会多出一个 `FF` | 解析时容忍多出来的 `FF` |
| 不知道是线的问题还是解析的问题 | 没有排查手段 | 屏幕显示每个基站收到的字节数：不涨 = 线没接对或没共地，涨了但没数据 = 解析问题 |
| 第四个基站数据进不来，屏幕 `B` 那行一直灰（11-01） | 用 ST-Link 不停机读内存：PA10 上一个字节都没收到；拔掉线、把 PA10 内部改成下拉，仍然读到高，说明板子上有东西一直把 PA10 拉高，基站 TX 压不过它。10-20 的 README 就提醒过板载 USB 串口可能接在 PA9 / PA10，没有原理图，没证实 | PA9 也读到高，但实测基站拉得动。USART1 改成单线模式（HDSEL），从 TX 脚 PA9 收、不发送，在 `uwb.c` 的 `UWB_UseBackAnchorPA9` 里切，CubeMX 不用改。先用 ST-Link 临时写寄存器验证能收，再改固件 |
| 第四个基站没有 5 V 排针可接 | 以为转接板必须接 5 V | 转接板原理图上没有稳压芯片，标 5V 的脚就是模块 VCC，规格书写 3 ~ 5 V、推荐 3.3 V；改接 TB6612 模块（D153C）J5 的 3V3。GPIO 不能供电（只有 3.3 V、单脚约 25 mA） |

### 2.4 UWB 方向

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 人在右边，屏幕却时不时显示 left（10-21） | 每个基站都分不清信标在它前面还是背面，背后的信号会镜像到前面。左右基站背靠背，人在右前 60° 时左基站读成左前 60°。原来"选读数离自己正前方最近的基站"会选中这个镜像 | 左右只听前基站：连续 3 帧在 ±60° 以内、同一边才换边 |
| 车往反方向拐（10-21），当时以为电机左右接反了 | 其实是三个基站发来的角度正负号都和厂家例程相反 | 10-21 先把电机左右对调（`MOTOR_SWAP_LR = 1`），跟随就对了 |
| 偶尔突然原地转（10-29 查出原因） | 上一行的两个错误正好抵消，小角度看不出来；大角度时 60° 被算成 120°，触发原地转。当时记的是"以前突然原地转多半是这个" | 角度正负号改对（`UWB_*_ANGLE_SIGN = -1`），电机对调改回 0。试电机时两轮同速，看不出左右反了，只有拐弯才看得出来 |
| 很难识别后方的信标，人在身后时狗往前走（11-01 前） | 人在正后方时前基站读数很小，又被当成正前方，135° 以外全错 | 加后基站，在前基站正后方约 36 cm、背对背。前后两个距离差 = -36 × cos(方向)，正后方时最大；左右基站的读数正好量"偏前还是偏后"。两者合成前后判断，带回差 |
| 用左右两个距离差判左右，一直误判 | 两个基站只隔 10 cm，规格书测距误差 ±5 cm；而且背对信标的基站信号绕着走，距离偏长。11-01 静止实测：信标在右后方约 30 cm 时左右距离差了 37 cm | 不再用距离差判左右，改听朝着信标的前 / 后基站读数的正负号 |
| 仿真里发现的三个问题（11-01，烧录前就修了） | ① 5 帧中值窗口里混进边缘翻号和粗差时，中值会落到另一边，人在侧面时左右卡错改不回来；② 前后两个基站都没数据时狗会一直往一边转；③ 后基站正负号配反时狗来回抽 | ① 5 帧全在 ±60° 以内、全部同号才算一票；② 不知道左右时，偏离不到 45° 就按正前方走；③ 后半圈换边要前基站的镜像读数不反对 |
| 人绕过正后方时，跟随测试模式的平滑角度会经过 0° | 角度从 +179° 跳到 -179°，直接相减平滑会穿过正前方 | 平滑改成走近路 |

### 2.5 跟随调参（跟随测试模式 `follow.c`，1 kg 左右的车，10 月上车实测）

| 版本 | 参数 | 上车结果 |
| --- | --- | --- |
| 1（MSPM0 原参数） | 起步 600，转向 = 角度 × 35 | 5 m 外才推得动，一直原地打转 |
| 2 | 起步 2200，转向 × 40，死区 5° | 能走了，拐弯太快、左右摆头 |
| 3 | 死区 15°，转向最多前进的 30% | 弯还是太急，1 m 宽的走廊来不及回正 |
| 4 | 死区 15°，每度 0.4%、最多 10% | 先直走，偏到 15° 外才猛打方向 |
| 5 | 死区 5°，每度 0.2%、最多 6%，方向盘慢打 | 好多了，偶尔突然原地转 |
| 6 | 原地转从 75° 改成 90°，并要保持 0.3 秒 | |
| 7 | 修好左右不分以后转向不灵敏：每度 0.25%、最多 8%，起步 3000 | |
| 8 | 距离系数 10，平滑 1/3，每度 0.3% | 没有大转弯了，但有点过于谨慎 |
| 9 | 方向盘每 20 ms 最多变 15，转向最多 10% | 摇摆明显，又有突变 |
| 10 | 取 8 和 9 的中间：每 20 ms 最多变 12，最多 9% | |
| 10-30（定版） | 改对 UWB 正负号以后：2 m 内停车，每度 0.4%、最多 10%，每 20 ms 最多变 15 | README 没记这一版的上车结果 |

关键是转向不再用"角度 × 系数"的绝对 PWM，而是按前进量的比例算，再限制每 20 ms 能变多少，弯的急缓和车速无关。FPGA 的 `mc_follow` 10-21 照这套移植，后来加了陀螺仪角度环，两边已经不一样。

### 2.6 和 FPGA 的通讯、供电

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| FPGA 屏幕 `UWB NOLK`，STM32 屏幕 `FPGA STOP` | 双排针奇偶两排看错，CEP 脚 4 在脚 3 的对面；后来 `NOLK` 和 `LOST` 交替是接触不良 | PB10 改接脚 4 并换线；FPGA 屏幕细分 `OK` / `LOST` / `NOLK` |
| FPGA 上下电时串口可能收不到 | 毛刺造成帧错，HAL 会把接收 DMA 停掉 | 错误回调里只置标志，主循环里重启 DMA |
| 接上 STM32 后整板挂掉，放几分钟又能用 | 电源带不动 | 换稳压 5 V，所有板子共地 |

### 2.7 尾巴（步进电机）

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 上电不回中 | 驱动器的坐标零点就是上电时的位置 | 单圈就近回零，再设坐标零点；回零的零点先在驱动器菜单里存一次 |
| 尾巴归谁来回改了几次 | 10-21 STM32 用来测驱动器，10-25 改回 STM32 驱动（主人 3 m 内摇），10-31 归 FPGA（喂食也要摇） | 最后归 FPGA；STM32 的尾巴任务停掉，USART1 给第四个基站，`HARDWARE/STEPPER/` 只留着对照协议 |

### 2.8 还没解决

| 问题 | 现状 |
| --- | --- |
| 四基站融合没在车跑起来时验证过 | 11-01 静止实测四路都有 40 帧/秒、错误 0，信标在右后方时方向对；2 ~ 3 m 的标定（README"UWB 上车标定"）还没做 |
| 电机转起来时供电够不够 | 后基站接 D153C 的 3V3，只在静止时试过 |

| PA10 是被什么拉高的 | 没有板子原理图，没证实是不是 USB 串口芯片 |
| 跟随测试模式 | 不避障；11-01 加第四个基站以后没上车跑过 |
| `follow.h` 有几行注释还是旧值 | 写着 0.3%、9%、12，实际是 0.4%、10%、15，以 README 为准；初赛前不改代码 |

## 3. 经验

- **两个错误会互相抵消**：UWB 正负号反了、电机左右也"接反了"，跟随看起来一直是对的，直到大角度才露馅。试电机时两轮同速，看不出左右，要单独拐弯试；每一环各自验证，不靠整体看起来对。
- **规格书不一定对**：版本号、转接板的"5V"都和实际不一样，先看线上实际的字节、原理图实际的网络。
- **屏幕上的排查信息很值**：每个基站收到多少字节、自己读到的角度距离，大部分接线问题第一眼就能分清是线、是解析还是算法。
- **ST-Link 可以不停机看现场**：HOTPLUG 模式读计数器和寄存器、临时改一个脚的上下拉，几分钟就定位了 PA10 的问题，比换线猜快得多；先用寄存器验证 PA9 能收，再改固件。
- **算法先在电脑上仿真**：用真实的解析和融合代码、假设的噪声，静态误差看着都好，闭环（照 FPGA 的转向逻辑让车转起来）才暴露"侧面左右卡错""一直转""来回抽"这种问题。
