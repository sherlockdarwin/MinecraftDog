# Verilog 模板

题目给 tb 和程序头，自己写设计文件，用 ModelSim 出波形验收。下面每个 .v 都能直接复制。

## 考场流程

1. 建一个**路径里没有中文**的文件夹，E:\FPGA\exam
2. 把题目的 tb 存成 `tb.v`；新建自己的 `.v`，把程序头整段贴进去（模块名、端口名、位宽一个字都不改）。把 `run.do` 复制进来。
3. 读 tb：时钟周期（`always #5 clk = ~clk` → 周期 10）、复位极性（`rst_n` 低有效，`i_rst` 高有效，看 tb 一开始给的值）、有没有 `$stop`、每段激励在测什么（tb 注释里一般写了）。
4. 选下面的模板往里填。
5. 改 `run.do` 前 4 行。VS Code 终端 `cd` 到这个文件夹，输入 `vsim -do run.do`。改完代码在 ModelSim 的 Transcript 里输入 `do run.do` 重跑。
6. 对照题目每一条要求查波形。右键信号 → Radix 改显示格式，BCD 用 Hexadecimal。

## 模板

- `t00_skeleton.v` 模块骨架 + 语法速查（数字写法、运算符、位宽、两种复位、5 条规则）。每题从这里开始。
- `t01_counter.v` 模 N 计数器（使能、进位）；加 / 减 / 置数计数器。
- `t02_bcd.v` 两位 BCD 计数；时分秒级联（例化写法看这里）；二进制和 BCD 互转；七段码。→ 电子钟
- `t03_fsm.v` 状态机 + 每个状态停 N 拍，三段式和一段式两种写法，功能相同，挑顺手的。→ 交通灯、密码锁、计费
- `t04_edge.v` 上升沿 / 下降沿检测；异步输入先打两拍。
- `t05_clkdiv.v` 偶数 / 奇数分频（占空比 50%）；每 N 拍一个脉冲。
- `t06_seq_detect.v` 序列检测（1011，可重叠），移位寄存器和状态机两种写法。
- `t07_shift_buffer.v` 4 位数字缓冲（输入 / 退格 / 清空）；串并转换。→ 密码锁
- `t08_timer.v` 保持 N 拍（开锁 10 拍、报警 50 拍）；冷却（触发后 N 拍内忽略）。→ 密码锁、交通灯
- `t09_saturate.v` 同一拍又加又减、不低于 0、不超上限。→ 计费
- `t10_pwm.v` PWM。
- `t11_debounce.v` 按键消抖。
- `t12_mem.v` RAM；同步 FIFO。
- `t14_for_loop.v` for 循环：数 1 的个数、位倒序，注释里有 tb 里的 for 写法。
- `t13_tb_template.v` testbench 写法：例化、时钟、task、wait、自动比较、超时保护。考试 tb 是给的，这个用来看懂 tb、自己补测。
- `run.do` ModelSim 一键脚本：编译、加载、加全部波形、运行。
- `tb/tb_t01.v` ~ `tb_t12.v` 每个模板的自检 tb。想看某个模板的波形：把整个文件夹复制到英文路径，`run.do` 里改成 `set TB tb_t03` 和 `set SRCS {t03_fsm.v tb/tb_t03.v}`，再 `vsim -do run.do`。

## 实测过的坑

- 中文路径：见考场流程第 1 条。
- `run.do` 的 `TB` 填成了自己的模块名（比如 `top`）：不报错，但仿真时间一直是 0、波形是平的——没有 tb 就没有时钟和输入。`TB` 一定填 tb 里 `module` 后面的名字。
- 原题 tb 没有 `$stop` 还用 `-all`：一直跑不停，只能点工具栏的 Break。`TIME` 改成时长。
- 原题 tb 在时钟上升沿的同一时刻用 `=` 改输入（计费题）：ModelSim 里你的模块在这个沿就看到新值。
- tb 里 `wait (x)` 在上升沿刚过就返回，紧接着的 `@(negedge clk)` 还在同一拍。
- 波形里看不到模块内部信号：仿真要加 `-voptargs=+acc`（`run.do` 已经加了）。
- `` `timescale ``：tb 有没有、设计文件有没有，7 种组合在 ModelSim 10.4 里都能跑。设计文件不写就行。
- 原题 tb 不一定覆盖全部要求（密码锁的 tb 没测"输满 4 位后再按"），波形对了还要对照题目逐条看。
- 考场纪律：禁止联网、禁止任何 AI（包括本地部署的）；全程 OBS 录屏，任务栏的时间要一直露出来。

## 补充：最近遇到的基础问题

### 拍、组合逻辑和下一状态

- 这些模板里一拍通常指相邻两个 `posedge clk` 之间的一个完整周期；时钟单次上升或下降只跨过半个周期（若占空比为 50%）。`always #5 clk=~clk` 的周期是 10 个时间单位。
- `always @(*)` 和 `assign` 是组合逻辑，输入改变后重新计算，不需要等时钟；`always @(posedge clk ...)` 在上升沿更新。低有效异步复位在 `rst_n` 下降时也立即生效。
- 例如 `T_GREEN=3`，进入绿灯时 `cnt=0`：绿灯的三个周期依次对应 `cnt=0、1、2`。当 `cnt==T_GREEN-1`，组合逻辑先把 `next_state` 算为黄灯，**下一个上升沿**才更新 `state`。这是从 0 开始计数的约定，不是所有计数器都机械地减 1。
- `case` 某个分支中有两条或更多语句，必须用 `begin ... end` 包起来。组合逻辑中的输出在每条路径都要赋值，常用默认赋值或完整 `default`，避免推断锁存器。
- 交通灯按钮既要判断 `ped_btn`，还要判断当前状态和冷却是否允许；只在真正接受按钮时启动冷却，否则红灯时按键也可能错误地开始冷却。

### 参数、位宽、波形和拼接

- `module m #(parameter W=8)(input [W-1:0] x);` 中 `#(...)` 是参数列表，后一个 `(...)` 是端口列表。`parameter` 能在例化时用 `#(.W(4))` 覆盖；`localparam` 用于模块内部常量。普通 Verilog 的参数应声明在模块参数列表或模块内部。
- `[1:0] light` 是 2 位总线，不是 3 个信号：只有 `light[1]` 和 `light[0]`，可表示 `00、01、10、11`。ModelSim 可以将总线作为一行看 Binary/Unsigned 值，也可展开看各位。`reg` 表示过程赋值变量，并不必然是寄存器。
- `{a,b}` 从左向右拼接；`{4{1'b1}}` 是重复四次得到 `4'b1111`。`[W-1:0]` 有 W 位，`[W:0]` 有 W+1 位，位编号从 0 开始。
- `cond ? A : B`：条件为真取 A，否则取 B。`{1'b0, add_val}` 是最高位补 0；`{(W+1){1'b0}}` 是 W+1 个 0。无符号加法先扩位可保存进位；有符号负数扩位须复制符号位，见 `t15_signed_sum.v`。
- 分频 `W` 是计数器的位宽，要足以表示所用终值。奇数 N 的 `div_odd` 先做高 `(N-1)/2` 拍、低 `(N+1)/2` 拍的波形，再和延迟半拍的副本相或。N=3 时输出稳态高、低各 1.5 个输入周期。

### 按键和序列

- `d <= {d[1:0], sig}` 是整个三位寄存器一起赋值，等价于 `d[0]<=sig; d[1]<=d[0]; d[2]<=d[1];`；三个右值取更新前的旧值。`d[0]、d[1]` 是两级同步，`d[2]` 用来保存上一拍以比较边沿。
- `key_d <= key_out; assign press = key_out & ~key_d;`：稳定按住时 `key_out` 可一直为 1，而 `press` 只在检测到 0→1 时高一拍。同步/边沿检测不能代替机械按键消抖；异步短脉冲也可能采不到。
- `t06` 的 `din` 每个上升沿输入一位。状态 `S0/S1/S2/S3/S4` 分别表示匹配了空、`1`、`10`、`101`、`1011`。失配时保留输入结尾中还能作为目标开头的最长部分：`11` 留下 `1`、`1010` 留下 `10`。`1011011` 可以重叠找到两次。
- 题目若要求每 N 位固定分组、不能跨组匹配，与 `t06` 的重叠检测不同；见 `t16_group_seq.v`。读题要确认结果是在最后一位采样后立即显示，还是还要再等一个上升沿。

### RAM 和 FIFO

- `reg [DW-1:0] mem [0:(1<<AW)-1];`：`DW` 是每格的数据位宽，`AW` 是地址位宽；`1 << AW` 是数字 1 左移 AW 位，即深度 `2^AW`。如 AW=3、DW=8，就是 8 格、每格 8 位。
- `fifo_sync` 的 `wr_en` 请求把 `din` 入队，`rd_en` 请求取走队头；`dout` 在非空时直接显示队头，上升沿取走后指向下一项。空时 `dout` 无效，须看 `empty`。
- 本模板以沿前 `full/empty` 判断是否接受：满时同时读写只读；空时同时读写只写；非空未满可同时读写，`count` 不变。实际题目的边界规则可能不同，要以题意为准。

## 补充：怎么看 `step` 和三道模拟题的检查结果

### `step(...)` 是什么

`step` 是之前编写 testbench 时自定义的 `task` 名，类似把一小段激励和检查包装成一个可重复调用的小过程，**不是 Verilog 的固定命令**。具体参数和顺序由该 tb 中 `task step` 后面的 `input` 声明决定。它会等下降沿设置输入，再等上升沿、延迟 1 ns 检查输出；参数里有些是预期结果，不是输入给设计的信号。

- 停车场 `step(1,0,2)`：`enter=1`、`leave=0`，预计上升沿后 `count=2`；第三个数是检查用的预期值。前面余额/计数要结合此前的步骤，例如先从 0 加到 1，再来一次才到 2。
- 洗衣机 `step(0,0,2)`：`start=0`、`stop=0`，预计该沿后 `phase=2`（漂洗）；同时检查 `busy`。
- 四位序列 `step(1,1,1,0)`：`valid=1`、`din=1`，预计该沿后 `match=1`、`not_match=0`。只有此前三位已经按题意组成 `101` 时，第四位 1 才应匹配成功。

`PASS` 表示该 tb 已执行的检查通过；`FAIL time=...` 给出检查时间、实际值和预期值。题目可能还有 tb 没覆盖的情况，仍需对照题意检查。查看波形时保留 `clk`、输入、输出；把多位值的 Radix 设为 Unsigned 或 Binary。新版 `../提高题与仿真` 的题目按逐条激励写 tb，可直接对照题目中的时间表看。

### 停车场：`test/q1/q1.v`

本次仿真 `PASS tb_parking`。例如 56 ns 检查到 1，96 ns 达到 5，满时继续进入仍为 5；126 ns 检查到离开后为 4，186 ns 检查到 0。同步进出、空满边界和对应标志通过现有 tb。

### 四位分组序列：`test/q2/q2.v`（模拟题三）

仿真在 76、116、156 ns 分别期望 `match/not_match = 10、01、10`，实际均为 `00`，共 3 处失败。关键问题：

1. `count`、`num` 需要记住已经接收的位，应在 `posedge clk` 且 `valid=1` 时更新；写在 `always @(*)` 的 `count = count+1` 并不会表示“每拍加一”，还可能产生组合反馈或锁存行为。
2. `count`、`num` 在复位时序块和组合块都被赋值；`match`、`not_match` 也被两个块赋值。同一寄存器应由一个过程块负责，否则会多驱动或竞争。
3. `match/not_match` 应在时序块复位时清 0，正常时先默认清 0，恰逢第 4 个有效位再按比较结果置 1，从而产生一拍脉冲。
4. 若 `num` 存前三位、当前 `din` 是第 4 位，比较可写 `if ({num[2:0],din} == 4'b1011)`；不要以为同一个时序块中的 `num <= {...}` 后马上读取到的是新值。`valid=0` 时保持组内计数和数据，但脉冲仍按时清零。

### 洗衣机：`test/q3/q3.v`（模拟题二）

仿真从 36 ns 开始应进入洗涤，但 `phase` 一直为 0；现有 tb 共报 15 处失败。`phase` 在时钟块里仅复位，没有正常运行时的 `phase <= next_phase`，因此不会离开待机。`cnt` 既在复位时序块赋值，又在 `always @(*)` 中赋值并自加；它也应在一个时钟块中更新。

可以先按思路分工：组合块只计算 `next_phase`；时钟块复位时清 `phase/cnt`，`stop` 时回待机并清计数，否则更新 `phase <= next_phase`，阶段改变时清 `cnt`，阶段未变且处于运行状态时每拍加一。这样 `stop` 才有实际优先级，状态持续的 4/3/2 拍才由时钟计数。输出 `busy=(phase!=S_IDLE)` 的思路是对的。

### 洗衣机修改后：当前状态、下一状态和赋值顺序

- `next_phase = phase;` 是把右边的当前状态复制到左边的下一状态，并没有修改 `phase`。后面的 `next_phase = S_WASH;` 也只是在计算下一状态；要让当前状态改变，需由时钟块在上升沿写 `phase <= next_phase;`。
- 时钟块使用 `phase = next_phase;` 后立刻判断 `phase != next_phase`，由于阻塞赋值已经改变了 `phase`，通常判断不到切换。使用 `phase <= next_phase;` 时，本次时钟块内的比较仍读旧 `phase`，可用于判断是否将要切换。
- `stop` 分支需要直接让 `phase <= S_IDLE; cnt <= 0;`；不能只改 `next_phase`。`next_phase` 由组合块负责，不要在时钟块中再赋值。
- 待机时计数器应清零；切换阶段时也清零。否则待机期间已经积累的计数可能让洗涤提前结束。
- 针对初学者和考试综合代码，记住一个寄存器由一个 `always` 块统一赋值；组合逻辑和时序逻辑分别管各自的变量。不同信号可放在同一个块，也可放在不同块；关键是同一信号不要由多个过程同时驱动。testbench 的激励和特殊电路另有例外，要以实际设计为准。
- 洗衣机再次修改时，不要漏掉组合块开头的 `next_phase = phase;`。例如待机且 `start=0` 时，若分支没有赋值、又没有默认值，`next_phase` 可能保持未知 X；下一上升沿 `phase <= next_phase` 会把 X 存进去。在临时副本中补回该默认赋值后，现有 `tb_washer` 仿真通过。

### 序列检测：有效输入暂停时，输出脉冲也要结束

`test/q2/q2.v` 修改后，分组和比较的主要路径已通过，剩余问题是 `valid=0` 时整个时钟块不再更新，导致上一拍的 `match/not_match` 维持高电平。现有仿真在 166、176 ns 期望 `match=0`，实际均为 1。`valid=0` 只要求保持已收到的数据和组内计数，不要求保持输出脉冲。

常用写法：在时钟块的非复位 `else` 内先默认 `match <= 0; not_match <= 0;`，再用 `if(valid)` 接收数据、计数；恰好完成一组时，在同一个块的后面根据比较把对应输出置 1。这样结果高一拍后，即使下一拍 `valid=0`，也会自动清零。临时副本用此思路已通过现有 `tb_seq4_group`。

### 2023 电梯题：原题波形和边界

`test/elevator/elevator.v` 在当前原题 tb 下，楼层 30→8→12、超员/超重报警的主要激励能表现出来；但原题 tb 没有 `$stop`，`run.do` 用 `-all` 会一直运行，应改有限时间，如 `900ns`。楼层用 Unsigned 更直观。原题只说超员、超重时报警，没有明确要求停止电梯，不要擅自把暂停当成原题要求。

补充测试：目标 H=41 时当前代码会从 1 上到 2，未限制最高 40 层；原题给了 `floor=40`，应检查目标上界。紧急标志 `k` 由 `posedge key` 块置位，又在 `posedge clk` 块清零，属于同一寄存器被两个过程驱动；且复位时未清零。测试中紧急运行中复位，N 清成 1 但 k 仍为 1，复位释放后在没有新的紧急沿时仍向 8 楼移动。初始 k 在仿真中是 X；在本次 ModelSim 运行中 `if(k)` 没有走真分支，正常目标仍能移动，但不能把未知值当成可靠复位。建议同步并边沿检测 key，在同一个 clk 时序块中统一复位、置位、清除紧急许可，具体时序要结合题意及按键脉宽确定。

### 游戏币：if 后面的 begin 要贴住条件

`test/game/game.v` 曾写成 `else if (boost == PLAY) last_boost <= boost; begin ... end`。没有 `begin` 时，if 只控制紧跟的一条赋值；后面的 `begin ... end` 是独立语句块，非复位的每拍都执行，导致普通模式也执行扣 2。应写成 `else if (boost == PLAY) begin last_boost <= boost; ... end`。在独立副本中只改这个位置后，原 tb 的普通模式扣费由每拍 2 变成每拍 1，但充值和体验逻辑仍需另外检查。

充值的 `remain_money = remain_money + money` 不应放在另一个组合块里同时驱动已在时钟块赋值的余额；同拍充值和扣费需按题意确定先后，先算出一次结果，再由同一时钟块更新余额。原 tb 的 `set` 和时钟上升沿恰巧重合，可能出现仿真竞争；自己补测时可在下降沿改变输入。

游戏币后续修改：`test/game/game.v` 用组合线 `cost` 算当拍费用、`sum` 保存余额加充值后的 11 位结果、`after_cost` 防止减到负数、`next_money` 限制到 10 位最大值；最终由同一个时钟块统一更新余额。进入体验的首拍算第 1 拍，第 5 拍结束后下一拍恢复收费。原题未写明再次尝试体验的模式规则，目前保留练习者的处理：沿用先前普通/畅玩模式；若体验中途关机，切回体验时继续先前计数。原题 tb 同沿改输入存在竞争，应再用下降沿改变输入的补充 tb 验证。

### t17：四个数从小到大排序

`t17_sort.v` 是四个无符号数的组合排序，`tb/tb_t17.v` 给出乱序、倒序、重复值、最大/最小值和相等值的激励。四个输入同时给出，输出 `out0` 最小、`out3` 最大；没有时钟，输入变化后输出跟着重新计算。例：`7、2、9、4 → 2、4、7、9`。比较采用阻塞赋值交换，保留重复值。

仿真：复制 `t17_sort.v`、`tb/tb_t17.v` 和 `run.do` 到英文路径；设 `TB tb_t17`、`SRCS {t17_sort.v tb_t17.v}`、`TIME -all`，数值格式选 `unsigned`。Transcript 的 `PASS tb_t17` 表示这五组检查通过。题目如果是串行输入、要求多拍完成或带负数，应另按接口、时序及 signed 要求改写。
