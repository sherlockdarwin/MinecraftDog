⏺ Found a real bug in game_count.v: when set (charge) and the per-cycle
  deduction both fire on the same clock edge, the deduction overwrites the
  charge because both assign r_remain in the same always block — the last
  assignment wins. That's why the trace showed set=1 money=15 but remain stayed
  at 0. I'll fix it by computing a single net remain value per cycle.

  1. 程序头、top、tb 的关系

  tb 不是 top。用 C 来类比：

  ┌─────────────┬──────┬────────────┬──────────────────────────────────────┐
  │    东西     │ 谁写 │ C 里相当于 │                 作用                 │
  ├─────────────┼──────┼────────────┼──────────────────────────────────────┤
  │ 程序头      │      │ 函数原型   │                                      │
  │ module      │ 题目 │ void       │ 规定模块名、端口名、位宽，一个字都不 │
  │ top(...);   │ 给   │ top(int    │ 能改                                 │
  │ endmodule   │      │ clk, ...); │                                      │
  ├─────────────┼──────┼────────────┼──────────────────────────────────────┤
  │ 你的设计文  │ 你写 │ 函数体     │ 在程序头里填逻辑，这部分就是 RTL     │
  │ 件          │      │            │                                      │
  ├─────────────┼──────┼────────────┼──────────────────────────────────────┤
  │ tb（testben │ 题目 │ 调用这个函 │ 产生时钟和复位，按时间给输入，把你的 │
  │ ch）        │ 给   │ 数的       │ 模块装进去跑                         │
  │             │      │ main()     │                                      │
  └─────────────┴──────┴────────────┴──────────────────────────────────────┘

  top 只是这道题给模块起的名字。密码锁那题叫 serial_lock，交通灯叫 traffic_butto
  n_ctrl。"顶层"的意思是设计里最外层的模块，这题你只写一个模块，它自然就是顶层。

  所以仿真就是两个文件：

  tb.v（题目给的，不用改）
   ├─ always #1 i_clk = ~i_clk;          产生时钟
   ├─ initial ...                        按时间改 i_rst
   └─ top test( .i_clk(i_clk), ... );    ← 把你的模块放进来
         └─ 你的设计文件

  top test(...) 这句里，top 是模块名（像 C 的类型名），test
  是实例名（像变量名）。.i_clk(i_clk) 左边是你模块的端口，右边是 tb
  里的信号，相当于按名字传参。tb 靠模块名找到你的代码，文件名随便取。比如
  answer/clock_12h.v 文件名不叫 top，里面写的是 module top，tb
  照样能用。模块名拼错会报 Unknown module type: top。

  2. 为什么一个文件就够

  对，因为题目小。大工程会拆成很多模块，再用顶层连起来，比如你 MinecraftDog 的
  mctop.v 里装了 mc_tick、mc_key、mc_behavior
  等几十个模块。考试这种题写一个模块最省事，也不容易连错线。

  3. RTL 和 Verilog

  Verilog 是语言。RTL（Register Transfer
  Level，寄存器传输级）是一种写法：把电路描述成"寄存器 +
  寄存器之间的计算"。寄存器在时钟沿存下新值，中间的组合逻辑算出下一个值。

  - 设计文件只用能变成电路的写法（always @(posedge clk)、assign、if/case），这叫
  RTL 代码。
  - tb 里的 #3 延时、initial、$stop 只在仿真里有意义，变不成电路，所以 tb 不是
  RTL。

  记住一条：#延时 只出现在 tb 里，设计文件里不要写。

  4. 从 C 过来要换掉的思维

  C 按顺序一条条执行。RTL 描述的是电路，所有 always 和 assign 同时、一直在工作。

  (1) 时钟就是主循环。 不要想 while(1){ ss++; sleep(1); }。每个时钟上升沿，所有
  always @(posedge i_clk) 块同时执行一次。

  (2) <= 读到的都是时钟沿之前的旧值。 同一个沿上，所有 <=
  的右边先用旧值算好，再一起更新：

  always @(posedge clk) begin
      a <= b;
      b <= a;     // a、b 交换了。C 里这么写不会交换
  end

  规则：带 posedge 的 always 里一律用 <=。

  (3) assign / wire 像 Excel 公式。 wire ss_full = (ss_l == 9);
  不是只算一次，ss_full 永远等于右边，ss_l 一变它跟着变。

  (4) 一个 reg 只在一个 always 里赋值。 同一个 always 里给同一个 reg
  赋两次，后一句覆盖前一句。上次游戏机计费的 bug 就是这样：充值和扣费各写了一句
  r_remain <= ...，扣费那句把充值盖掉了。

  (5) 需要"记住"的量就是 reg。 把电子钟写成 C，就能看出 RTL
  在干什么（为了好懂这里用普通十进制，不是 BCD）：

  // 每个时钟上升沿调用一次；ss、mm、hh、pm 是全局变量，相当于 reg
  void on_posedge(void) {
      // 先用旧值把条件都算好（Verilog 的 <= 自动做了这一步）
      int ss_full = (ss == 59), mm_full = (mm == 59), hh_full = (hh == 11);

      if (rst) { ss = mm = hh = pm = 0; return; }   // 
  先判复位，所以复位优先于使能
      if (!ena) return;

      ss = ss_full ? 0 : ss + 1;
      if (ss_full)                       mm = mm_full ? 0 : mm + 1;
      if (ss_full && mm_full)            hh = hh_full ? 0 : hh + 1;
      if (ss_full && mm_full && hh_full) pm = !pm;
  }

  5. 二进制和十进制有没有区别

  对电路没有区别，只影响你读起来方不方便。格式是 位宽'进制 数值：

  2'd2  ==  2'b10  ==  2'h2      // 都是两根线：1、0

  状态机里 localparam S_IDLE = 2'd0, S_RUN = 2'd1, S_LOCKED = 2'd2; 换成 2'b00, 
  2'b01, 2'b10 完全一样。状态编号只是标签，互不相同、位宽装得下就行（2 位最多 4
  个状态）。我的习惯是计数和状态用十进制；题目用二进制给的（比如 boost 的
  2'b10）就照抄，方便对照题目。

  要小心的是另外两件事：

  - 位宽：2'd5 只留低 2 位，变成 1。4 位的 4'd15 + 1 会回到 0。
  - BCD 不是十进制，这正是电子钟的坑。BCD 的 59 是 0101_1001，要写 8'h59；8'd59
  是 0011_1011。如果用 8 位存 BCD，又写 if (o_ss == 
  8'd59)，这个条件永远不成立。下面的代码把十位、个位分开存，比较时写 ss_l == 
  4'd9，就避开了这个问题。

  第一步：读题，列端口表

  ┌────────────────────┬──────┬──────┬─────────────────────────────┐
  │        端口        │ 方向 │ 位宽 │            含义             │
  ├────────────────────┼──────┼──────┼─────────────────────────────┤
  │ i_clk              │ 入   │ 1    │ 时钟，每个上升沿 = 1 秒     │
  ├────────────────────┼──────┼──────┼─────────────────────────────┤
  │ i_rst              │ 入   │ 1    │ 复位，高电平有效            │
  ├────────────────────┼──────┼──────┼─────────────────────────────┤
  │ i_ena              │ 入   │ 1    │ 使能，为 1 才走时           │
  ├────────────────────┼──────┼──────┼─────────────────────────────┤
  │ o_pm               │ 出   │ 1    │ 0 上午，1 下午              │
  ├────────────────────┼──────┼──────┼─────────────────────────────┤
  │ o_hh / o_mm / o_ss │ 出   │ 8    │ BCD，[7:4] 十位，[3:0] 个位 │
  └────────────────────┴──────┴──────┴─────────────────────────────┘

  复位极性这样判断：名字是 i_rst，不带 _n，而且 tb 开头 i_rst = 1，所以 1
  有效，代码写 if (i_rst)。另外几题用的是 rst_n，低有效，写 if 
  (!rst_n)。写反了，整段仿真都是错的。

  第二步：读 tb，弄清考官怎么测

  always #1 i_clk = ~i_clk;   // 每 1ns 翻一次，周期 2ns
  initial begin
      #3 i_rst <= 0;          // t=3  松开复位，开始走
      #7 i_rst <= 1;          // t=10 中途再复位一次
      #3 i_rst <= 0;          // t=13 再松开

  能读出三件事：
  1. 一个时钟就是一秒。50 万秒约 139 小时，上午/下午会切换 11
  次。不要自己加分频，加了波形里时间就不动了。
  2. tb 故意中途复位一次，看你能不能回到 00:00:00。
  3. i_ena 一直是 1，tb 没测使能。但题目要求了，照样要写。

  第三步：拆功能

  像汽车里程表一样逐级进位：
  - 秒：00→59 循环
  - 分：秒为 59 的那一拍 +1
  - 时：秒和分都是 59 的那一拍 +1，00→11 循环
  - pm：11:59:59 → 00:00:00 那一拍翻转

  每一级只回答两个问题：复位时是多少？什么条件下变成什么？ 以秒为例：

  ┌───────────────────────┬──────────────────────────────────────┐
  │         当前          │                下一拍                │
  ├───────────────────────┼──────────────────────────────────────┤
  │ 59                    │ 00（同时 ss_full = 1，通知分钟进位） │
  ├───────────────────────┼──────────────────────────────────────┤
  │ 个位是 9（09、19…49） │ 十位 +1，个位归 0                    │
  ├───────────────────────┼──────────────────────────────────────┤
  │ 其他                  │ 个位 +1                              │
  └───────────────────────┴──────────────────────────────────────┘

  第四步：写代码

  module top(
      input          i_clk,
      input          i_rst,
      input          i_ena,
      output         o_pm,
      output [7 : 0] o_hh,
      output [7 : 0] o_mm,
      output [7 : 0] o_ss
  );

  // 要记住的量 → reg。每个十进制位用 4 位存（能装 0~15，够放 0~9）
  reg [3:0] ss_h, ss_l;     // 秒的十位、个位
  reg [3:0] mm_h, mm_l;     // 分
  reg [3:0] hh_h, hh_l;     // 时
  reg       pm;

  // 进位条件 → wire，永远等于右边的表达式
  wire ss_full = (ss_h == 4'd5) && (ss_l == 4'd9);    // 秒 = 59
  wire mm_full = (mm_h == 4'd5) && (mm_l == 4'd9);    // 分 = 59
  wire hh_full = (hh_h == 4'd1) && (hh_l == 4'd1);    // 时 = 11

  // 秒：每个时钟沿走一格
  always @(posedge i_clk) begin
      if (i_rst) begin                        // 先判复位 → 复位优先于使能
          ss_h <= 4'd0; ss_l <= 4'd0;
      end else if (i_ena) begin
          if (ss_full) begin                  // 59 → 00
              ss_h <= 4'd0; ss_l <= 4'd0;
          end else if (ss_l == 4'd9) begin    // x9 → 十位 +1，个位归 0
              ss_h <= ss_h + 4'd1; ss_l <= 4'd0;
          end else begin                      // 其他：个位 +1
              ss_l <= ss_l + 4'd1;
          end
      end
  end

  // 分：只在秒 = 59 的那一拍走一格
  always @(posedge i_clk) begin
      if (i_rst) begin
          mm_h <= 4'd0; mm_l <= 4'd0;
      end else if (i_ena && ss_full) begin
          if (mm_full) begin
              mm_h <= 4'd0; mm_l <= 4'd0;
          end else if (mm_l == 4'd9) begin
              mm_h <= mm_h + 4'd1; mm_l <= 4'd0;
          end else begin
              mm_l <= mm_l + 4'd1;
          end
      end
  end

  // 时：秒和分都是 59 的那一拍走一格，11 之后回 00
  always @(posedge i_clk) begin
      if (i_rst) begin
          hh_h <= 4'd0; hh_l <= 4'd0;
      end else if (i_ena && ss_full && mm_full) begin
          if (hh_full) begin
              hh_h <= 4'd0; hh_l <= 4'd0;
          end else if (hh_l == 4'd9) begin    // 09 → 10
              hh_h <= hh_h + 4'd1; hh_l <= 4'd0;
          end else begin
              hh_l <= hh_l + 4'd1;
          end
      end
  end

  // 上午/下午：11:59:59 → 00:00:00 那一拍翻转
  always @(posedge i_clk) begin
      if (i_rst)
          pm <= 1'b0;
      else if (i_ena && ss_full && mm_full && hh_full)
          pm <= ~pm;
  end

  // 程序头里的输出没写 reg，默认是 wire，用 assign 接出去。{a, b} 是拼接
  assign o_ss = {ss_h, ss_l};
  assign o_mm = {mm_h, mm_l};
  assign o_hh = {hh_h, hh_l};
  assign o_pm = pm;

  endmodule

  几个关键点：
  - 程序头原样抄。这题的输出写的是 output [7:0] o_ss，没有 reg，所以内部另开 reg
  存，最后用 assign 接出去。交通灯那题程序头是 output reg [1:0] 
  main_light，那题就直接在 always 里给它赋值。
  - if (i_rst) ... else if (i_ena)：先判复位，题目"复位优先于使能"这条就满足了。
  - 分钟块的条件是 i_ena && ss_full。秒从 59 变 00 的那个时钟沿上，ss_full
  读到的还是旧值 59，所以分钟正好 +1。这就是第 4 节说的"<= 读旧值"。
  - 这里是同步复位（敏感表只有 posedge i_clk）。写成异步的 always @(posedge 
  i_clk or posedge i_rst) 也能过这个 tb。
