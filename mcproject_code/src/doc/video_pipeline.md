# 视频通路说明：摄像头 → 屏幕（竖屏）

IMX415 ─MIPI CSI 4lane─► 取窗 ─► ISP ─► DDR2 帧缓存 ─► MIPI DSI 4lane ─► 10.1" 800×1280 屏。
状态：2026-10-05 第一次接屏上板，画面是**竖条纹（像条形码）、文字和状态方块被压扁 / 出现两层、整屏不停抖、偶尔全黑**。已按 §6 第一行改（水平消隐照抄厂商例程）+ 白平衡改成逐帧算（§9），仿真通过、TD 完整流程通过，**还没再上板**。
按键、文字区、尾巴、霍尔见 [`hmi_tail.md`](hmi_tail.md)；音频见 [`audio.md`](audio.md)；它们和视频通路互不依赖，只是文字层挂在 `mc_mixer` 里。

## 1. 架构

```
 CSI 口 ◄── IMX415                                                          DSI 口 ──► 10.1" 屏
   │ I2C / INCK / RST                                                        ▲ MIPI 4lane    ▲ 背光 / 复位
   ▼                                                                         │               │
┌─────── mc_cam_if 摄像头接口（时钟 = MIPI RX 字节时钟 111.4 MHz）─────────┐ ┌──── mc_disp_if 显示接口（时钟 = DSI 字节时钟 68.49 MHz）────┐
│ mc_cam_pwrup → uicfgimx415(I2C) ◄ ae_set(SW2/SW3 短按调增益)            │ │ mc_panel_ctrl → display_config_wrapper(ROM: ILI9881C 初始化)  │
│ D-PHY RX → csi_unpacket_4lane → raw10_unpacket_4lane → mc_crop(取窗)     │ │ video_tpg(时序) → mc_mixer(画布版面：相机窗口/状态方块/文字层)│
│        → isp_top(去马赛克 + 白平衡) → 128bit 打包 RGB 像素流             │ │ → rgb_24b_to_32b → dsi_video_mode_packet → D-PHY TX          │
└────────────────────────────┬─────────────────────────────────────────────┘ └──────────▲──────────────────────────▲───────────────────────┘
                             │ 像素流                                                   读使能 / 像素 │
                             ▼                                                                       │
                     ┌─────────── mc_framebuf 帧缓存（时钟 = DDR 用户时钟 132.8 MHz）─────────────────┴──┐
                     │ video_in ─► mc_to_user_interface ─► DDR2 控制器 ◄── video_out（厂商，顺序读）      │
                     │ （写入：4 缓冲轮换）                                                                │
                     └────────────────────────────────────────────────────────────────────────────────────┘
mctop：PLL（100 / 24 / 52.17 / 10 MHz）· 复位同步 · mc_tick · 状态汇总 → LED + 画面上的 8 个状态方块
```

三个块之间只传"像素流"和少量状态位；跨时钟域都用同步器或异步 FIFO。**以后加避障：在 `mc_cam_if` 的像素流上并联分析模块，在 `mc_mixer` 里把处理结果 + 框画到屏幕下半部分。**

## 3. 接线

| 底板连接器 | 接什么 | 排线 |
| --- | --- | --- |
| **CSI**（底板下沿左边那个，丝印 `CSI`） | CAM002 摄像头 | CAM002 随附的 40P 排线 |
| **DSI**（底板下沿右边那个，丝印 `DSI`） | 10.1" 屏 | 屏幕软排线：**标 `MLK` 的一端接底板 DSI 座，标 `LCM` 的一端接屏幕的 40P 座** |

- 断电后插拔；两个座都是后掀式：掀起锁扣 → 排线插到底 → 压回锁扣。参照厂商教程第 78 页照片：CSI 排线蓝色加强片朝上；DSI 排线印 `MLK` / `PCBA` 的一面朝上，`1` 号脚标记在右端。
- 屏幕资料图里的 40pin 定义和底板 DSI 座逐脚一致（直通排线）。
- 供电：5V/3A 以上的稳压适配器接 Type-C。**不要热插拔 JTAG。**

## 4. 屏幕版面（只做竖屏 800 宽 × 1280 高）

坐标 (u, v)：u 向右、v 向下，单位像素。**上半相机、中间状态带、下半留给避障**：

| 区域 | 坐标 | 做什么 |
| --- | --- | --- |
| **相机窗口** | u 0~799，v 0~559（800×560） | 传感器正中 800×560 的裁切（约整幅画面的 42%×52%，**不拉伸、不缩放**）。没有相机帧时是黑色 |
| **状态方块** | v 568~607，u = 40 + 90k（k = 0~7），每个 80×40 | 绿 = 1 / 红 = 0，从左到右：`[0]` 心跳（每秒红绿交替）｜`[1]` DDR2 校准完成｜`[2]` 屏幕初始化脚本发完｜`[3]` 相机寄存器配完｜`[4]` 收到 MIPI 帧｜`[5]` ISP 帧进入帧缓存｜`[6]` 无 MIPI 通道错误｜`[7]` 常绿（红绿色序参考） |
| **文字区** | u 40~759，v 616~711（45 列 × 3 行，每字符 16×32） | 黑底白字：增益 / 霍尔 / 尾巴 / 按键 / 开机秒数、音频状态、按键提示（`hmi_tail.md` §4） |
| **下半** | v 720~1279（800×560，和相机窗口一样大） | **黑色，留给避障**：以后放"处理后的画面 + 画框" |

```
v = 0    ┌────────────────────────────┐
         │ 相机窗口 800×560           │
v = 559  ├────────────────────────────┤
v = 568  │ ■ ■ ■ ■ ■ ■ ■ ■  (80×40)   │  状态带
v = 616  │ GAIN 050  HALL 0  TAIL ... │  3 行文字
v = 711  │ ...                         │
v = 720  ├────────────────────────────┤
         │ 黑（800×560，留给避障）     │
```

叠放顺序（从上到下）：文字层 > 相机窗口 > 状态方块 > 背景（`tb_mixer` 用重叠版面核对过）。版面参数只在 `mctop.v` 配置区改。

## 5. 上板步骤与预期现象

1. TD 里 Generate Bitstream → 下载（也可以直接下载 `src/boot/MinecraftDog_FPGA.bit`）。
2. LED1 约 1 Hz 闪。约 0.3 s 后屏幕背光亮，出现状态方块和文字（相机没接也会出现）；LED2 常亮。
3. 接了相机：LED3 常亮，屏幕上半部分出现**稳定**的实时画面；方块 `[3] [4] [5] [6]` 绿。
4. 曝光不合适：SW2 短按增益 +1、SW3 短按增益 -1（文字第 0 行 `GAIN`）。
5. 白平衡：上电后几帧内颜色逐渐变正（增益每帧走剩余差距的 1/4，十几帧收敛）。
6. **想先只验证屏幕链路**（不看相机）：`mctop.v` 的 `BG_PATTERN` 改 1，没内容的地方会显示测试图案（马赛克）。

## 7. 显示时序（为什么是这几个数）

- DSI 字节时钟 = 52.17 MHz × (`DPLL_MULTI_RATIO` + 1) / 16 = **68.49 MHz**（TD 时序报告里推出来的值，和厂商 7 寸屏例程一样），每通道 548 Mbps。整条显示流水线跑在这个时钟上，1 个时钟 = 1 个像素。
- **水平**：有效 800 + HSA 24 + HBP 136 + HFP 160 = 1120。**消隐和厂商例程一字不差**：加密的 DSI 打包核不看 D-PHY 的 `ready`（`APUG042` 图 2-5：一个高速包发完，`ready` 要拉低到回到 LP 才能发下一个），只靠消隐时间留出空隙。以前给的 24/100/76（共 200 个时钟，比厂商少 120 个）上板就出了 §6 第一行的现象。**不要再压缩水平消隐。**
- **垂直**：有效 1280 + VSA 6 + VBP 15 + VFP 16 = 1317（ILI9881C 10.1" 面板的典型值，Linux 内核 K101-IM2BYL02）。
- 刷新率 = 68.49 MHz / (1120 × 1317) ≈ **46.4 Hz**。相机 60 帧，显示端读"往前数第 2 帧"（4 缓冲），不撕裂。画面稳定以后想要 60 Hz：把 `DPLL_MULTI_RATIO` 改成 26（88.0 MHz、每通道 704 Mbps，≈ 59.7 Hz），时序余量够（显示时钟域现在能跑到 170 MHz 以上），但这会改变 DSI 速率，要上板确认。
- 初始化脚本的 ROM 格式已用厂商资料核对：`01 长度 数据…` = DCS 长包（厂商另一个屏的 ROM `config_data_nes.mif` 就是这样写的）、`02 寄存器 值`、`03 命令`、`04` + 4 字节延时（10 MHz 计数）、`05` 结束。

## 8. 约束：IO 约束和时序约束

- **IO 约束**（`mc_pin.adc`）≈ STM32 CubeMX 里"哪个引脚复用成什么功能、输出什么电平"。
- **时序约束**（`mc_timing.sdc`）≈ STM32 的时钟树配置：告诉工具每个时钟多快，布线后检查"逻辑能不能跑到这个频率"。SDC **只是告诉工具，不会改变真实频率**。
- TD 里改：Hierarchy 里展开 `constraint_1`，双击 `mc_pin.adc` / `mc_timing.sdc` 直接改文本，保存（最稳）；或 **Tools → IO Constraint** / **Tools → Timing Wizard**。输入脚不能写 `DRIVESTRENGTH`。

## 10. 仿真与已知风险

- `tb_fb`：帧缓存（真实 `video_in` / `video_out` / 厂商 FIFO + 行为级 DDR）逐像素核对，含相机高速写的压力用例。
- `tb_mixer`：屏幕合成器（缩小版面，整帧逐像素核对，4 个实例）。
- `tb_awb`：白平衡用测试台自己的模型逐像素核对（统计规则、亮像素边界 720 / 719、除法、限幅、平滑、帧边界换增益、乘法饱和、帧开始到第一个输出像素 ≥ 45 个时钟、每行最后一拍的 `O_tlast`），26 帧覆盖偏色收敛 / 限幅 / 全亮帧 / 增益 < 1；做过 35 个突变检查。延迟线里的 RAM 用行为级替身（`sim/stubs/stub_awb_delay_ram.v`）。
