# 按键 / 文字层 / 尾巴 / 霍尔 / 行为层 说明

三个按键、屏幕中间状态带里的 3 行文字（像 OLED 一样显示英文和数字）、步进电机尾巴（UART 只发不收：上电自动回零 + 喂食时左右摇摆）、霍尔传感器（喂食检测）和行为层（喂食时摇尾巴 + 放进食音效）。**接线见 [`pinout.md`](pinout.md)**；音频见 [`audio.md`](audio.md)；屏幕版面见 [`video_pipeline.md`](video_pipeline.md) §4。轮子的控制不在 FPGA 里（放在另一块单片机上）。
状态：每个模块都有测试台，用 Icarus Verilog 仿真通过（`bash tools/sim.sh`）；整套 RTL 用 TD 跑通综合 + 布局布线。按键 / 尾巴 / 霍尔**上过板但当时尾巴没动**（原因见 §3），这一版改了以后**还没上板**。

## 1. 架构

```
SW1 SW2 SW3 ─► mc_key ──短按脉冲──► mc_bench（SW2/SW3 短按 → 相机增益键）
 (R10 N2 J14)   10 ms 扫描
   mc_osd_dash（把状态排成 3 行文字）──写总线──► mc_disp_if 里的 mc_mixer → mc_osd_text → 屏幕中间状态带

霍尔传感器 ─► mc_hall（同步 + 去抖 20 ms）─ 喂食 = 1 ─► mc_behavior（行为层）─ 摇尾巴脉冲 ─► mc_tail ─UART 115200（只发）─► ZDT X42S 步进驱动器 → 尾巴
 (CEP 脚 17)                                                  └ 音效命令（2.wav）──────► mc_audio
```

行为层 `mc_behavior`（以后避障、跟随的状态机也放在这一层）现在做两件事：**喂食（霍尔 = 1）时**，① 尾巴摇一个来回（约 0.6 秒），摇完检查一次，磁铁还在就再摇一个来回，拿开以后把当前这个来回摇完就停；② 进食音效播一遍（播放中不重复触发，磁铁不拿开也不重播，拿开再靠近才再播）。预留了 `I_near`（以后 UWB 距离 < 5 m 时也这样摇尾巴）和 `I_bark`（以后 UWB 丢了 / 太远就狗叫，一直为 1 就循环叫），现在顶层接 0。

- **没有"函数调用"，只有模块 + 端口**：每个模块是一块一直在运行的硬件，状态机"调用"它 = 给它的输入端口一个命令（电平或脉冲），再看它的输出端口（busy / 读数）。见 §5。
- 所有模块跑在 100 MHz 系统时钟域，用 `mc_tick` 的 1 ms / 10 ms / 100 ms 脉冲做节拍（按键 10 ms 扫描、尾巴按 1 ms 计时、屏幕文字 100 ms 刷新）。

## 3. 尾巴：上电回零，以及上次上板尾巴为什么没动

**上电回零是怎么做的**：驱动器的"坐标零点"= 它上电那一刻的位置，所以以前发"回到绝对位置 0"等于原地不动（上次上板"上电没归位"就是这个原因）。现在改用驱动器自己的**单圈就近回零**（手册 5.4.2，`01 9A 00 00 6B`）：驱动器带单圈绝对编码器，会转到它存的"回零零点"，最多转半圈；FPGA 等 2 秒（`TAIL_HOME_MS`）再发"设坐标零点"（`01 0A 6D 6B`），之后摇摆的"绝对位置 0"就是正中。上电（和 SW1 按住 2 秒整机复位）后 1 秒（`TAIL_INIT_MS`）自动做一遍。

**回零零点要先在驱动器上设一次**（掉电不丢）：先拔掉 FPGA 到驱动器 R/A/H 的那根线 → 驱动器断电 → 用手把尾巴拧到正中 → 驱动器上电 → 驱动器菜单 `0_Set` → `Set 0` → 插回线。

**霍尔 = 1 时尾巴也没动，最可能是串口没通**（FPGA 发出去驱动器没收到）。逐条查：
1. 线：FPGA 的 CEP **脚 15**（E17）接驱动器的 **R/A/H** 脚（不是 T/B/L）；驱动器的 **Gnd 接 CEP 脚 2**。不共地串口收不到。
2. 驱动器必须是**串口 TTL 版本**（RS485 版本的 R/A/H 是差分电平）。
3. 驱动器菜单（出厂值）：`FWType = FW_Emm`（小屏第二行显示 `0.00err` 就是 Emm 固件）、`P_Serial = UART_FUN`、`UartBaud = 115200`、`ID_Addr = 1`、`Checksum = 0x6B`。
4. 驱动器电源 10~29 V 要接着（只插 FPGA 那根线它不会动）；小屏有显示、没报 `Clogging Protect`（堵转保护，FPGA 上电会先发解除保护）。
5. 确认霍尔真的到了 FPGA：屏幕中间第 1 行 `HALL 1`；看不到屏幕时，喂食时右喇叭会放 2.wav（音效和尾巴是同一个触发）。
6. 还不动：用 USB 转 TTL 模块接驱动器，在串口助手里手动发 `01 F3 AB 01 00 6B`（使能）、`01 FD 01 00 50 00 00 00 01 0B 01 00 6B`（转 30°），驱动器动了说明驱动器没问题、问题在 FPGA 这一侧的线。

## 4. 按键、屏幕文字、LED

| 键 | 功能 |
| --- | --- |
| SW1 短按 | 无 |
| **SW1 按住 2 秒** | **整机复位**（顶层 `mc_hold_reset`；尾巴会重新回零、背景音乐重新开始） |
| SW2 短按 / SW3 短按 | 相机增益 +1 / -1（台架把短按变成 40 ms 低电平脉冲送给相机增益模块 `ae_set`） |
| 各键长按 | 无 |

屏幕中间状态带（v 560~719）：上面 8 个状态方块（见 `video_pipeline.md` §4），下面 3 行文字（45 列，每个字符 16×32 像素，黑底白字）：

```
GAIN 050  HALL 0  TAIL IDLE KEY 000 UP 00123s      相机增益 / 霍尔（1 = 磁铁靠近）/ 尾巴（IDLE 空闲 HOME 回零 WAG 摇摆）/ 三个键的电平 / 开机秒数
SD READY  CODEC OK    BGM PLAY  SFX IDLE           TF 卡 / ES8388 / 背景音乐 / 音效（含义见 audio.md）
K3 SHORT  SW2 gain+ SW3 gain- SW1 2s reset         最近一次按键事件 / 按键提示
```

### 4.1 LED 的含义（没有屏幕、或屏幕不亮时）

| LED | 现象 | 含义 |
| --- | --- | --- |
| LED1 | 约 1 Hz 闪 | PLL 锁定、节拍正常（FPGA 在正常跑）。不闪 = 没配置好 / 时钟没起来 |
| LED2 | 灭 | DDR2 还没校准完（或校准失败） |
| | 约 2 Hz 闪 | DDR2 校准好了，屏幕初始化脚本还没发完 |
| | **常亮** | DDR2 校准好 + 屏幕初始化脚本发完。**没接屏幕也会常亮**（脚本只往屏幕写、不等应答） |
| LED3 | 灭 | 相机寄存器还没配完 |
| | 约 2 Hz 闪 | 相机寄存器配完了，但没有图像帧进来（**没接相机就是这样**） |
| | 常亮 | 图像帧持续进入帧缓存（相机、MIPI、ISP 都正常） |

### 4.2 上电以后应该看到什么

1. LED1 闪；约 0.3 s 后屏幕背光亮、状态方块和文字出现；LED2 常亮。接了相机：LED3 常亮，屏幕上半部分出现实时画面。
2. 约 1 秒：尾巴自己转到回零零点（正中）；屏幕 `TAIL HOME` 约 2 秒后回到 `IDLE`。
3. 约 1 秒：左喇叭（J12）开始放 1.wav，循环。
4. 磁铁靠近霍尔：`HALL 1`，尾巴摇一个来回（磁铁还在就继续摇），右喇叭（J11）放一遍 2.wav。

## 5. 在状态机里怎么"调用"（接口速查）

Verilog 里没有函数调用。对应关系：**函数 = 模块；调用 = 给输入端口赋值；参数 = 输入端口或 parameter；返回值 = 输出端口；`delay_ms` 阻塞 = 状态机里数 tick**。

| 模块 | 输入（你给） | 输出（你读） |
| --- | --- | --- |
| `mc_key` | `I_key[2:0]`（引脚）、`I_tick`（10 ms） | `O_short[i]` 短按脉冲、`O_long[i]` 长按脉冲、`O_pressed[i]` 按着中、`O_down[i]` 按下确认脉冲 |
| `mc_tail` | `I_cmd_wag` 脉冲（空闲且回零做完才收） | `O_busy`、`O_seq`（0 空闲 1 回零 2 摇摆） |
| `mc_audio` | `I_sfx_play` + `I_sfx_clip`（1~64）脉冲 | `O_ready`、`O_bgm_state` / `O_sfx_state`（0 空闲 1 打开中 2 播放中 3 出错）、`O_sfx_busy` 等（`audio.md` §5） |
| `mc_hall` | `I_hall`（引脚）、`I_tick_1ms` | `O_fed`（1 = 磁铁靠近，已去抖） |
| `mc_behavior` | `I_hall`（喂食）、`I_near` / `I_bark`（预留）；`I_audio_ready` `I_sfx_busy` `I_sfx_state` `I_tail_busy`（反馈） | `O_tail_wag`（接 `mc_tail`）、`O_sfx_play` + `O_sfx_clip`（接 `mc_audio`） |
| `mc_bench` | `I_key_short`、`I_tick_10ms` | `O_cam_key_n`（相机增益键） |
| `mc_osd_dash` | 各种状态量、`I_tick_1ms` `I_tick_100ms` | 写总线 `O_bus`（接 `mc_osd_text`） |

屏幕加一项显示：改 `tools/gen_osd_dash.pl` 里的 `@ITEMS`（一行 = 一个项目：固定字符串 / 状态名 / 数字，写明行、列、位数），要显示新的信号就在 `@SRC`（数字）或 `%SELID`（状态名）里加取值来源，并给 `mc_osd_dash` 加一个输入端口，然后 `perl tools/gen_osd_dash.pl > mcproject_code/src/rtl/video/osd/mc_osd_dash.v` 重新生成。

测试台验证的是 RTL 的逻辑；**它们不能替代上板**（引脚电平、驱动器真实响应、机械方向、真实 DDR 的读效率、真实 TF 卡的兼容性都要实测）。

**突变检查**（故意改坏 RTL 一处，测试台必须报 FAIL）：每个自写模块的接线、状态机、地址运算、边界条件都做过，抓到的测试台漏洞都已补上。下面是**没被抓到的等价突变**（改了以后外部行为一模一样，或者改的是重复的保险），以后别再追：

| 改坏的地方 | 为什么抓不到（不是测试台的漏洞） |
| --- | --- |
| `mc_tail`：`S_homed`（回零做完）在任何动作结束时置 1 / 在回零开始时就置 1 | `S_homed` 只在空闲时看；回零是上电后第一个动作，回零期间状态机不空闲，两种写法对外一样 |
| `awb`：本帧增益寄存器的复位值改成 2.0 | 第一个帧开始时就被换成"下一帧增益"（1.0），在那之前没有像素用到它 |
| `mc_hall`：把同步后的输入 `S_sync[1]` 换成 `S_sync[0]`（少一级同步） | 仿真里没有亚稳态，只差一个时钟，去抖是按毫秒数的；少一级同步的代价只在真实硬件上，所以保留两级 |
| `mc_hall`：翻转时 `O_fed <= S_in` 写成 `O_fed <= ~O_fed` | 翻转的条件是 `S_in != O_fed`，这时 `S_in` 就等于 `~O_fed` |
| `mc_mixer`：帧起始处锁存相机帧标志时，用 `I_vsync` 的电平代替上升沿 | vsync 脉冲期间不在有效视频里，锁存发生在脉冲开头还是结尾，窗口都在这之后才开始读 |
| `mc_audio_mix`：原生采样率（≥ 47500 Hz）的"每帧取一次"写成"每帧加 FS8 + 1" | 原生采样率下取样判断恒为真；累加值要连续播 13 秒以上才会溢出 20 位 |
| `mc_osd_dash`（生成的文字面板）：字符串项目的长度字段 +1，而这个项目后面紧挨着（同一行、下一格）就是下一个项目：`"GAIN "` `"HALL "` `"TAIL "` `"KEY "` `"UP "` `"SD "` `"CODEC "` `"BGM "` `"SFX "`、开机秒数多一位（被 `"s"` 盖掉）；`"s"`（多写的落在第 45 列，文字区外）；按键提示（多写的是空格） | 序列器按项目表的顺序写，多写的那一格随后被下一个项目覆盖，每 100 ms 只在写的那几百纳秒里错一格（`"GAIN "` 那一条在测试里碰巧在这几百纳秒里取样被抓到过）。别的项目的列 +1、行 −1、选择器 +1、文字表地址 +1、取值来源 +1 全部被抓到 |
| `mc_osd_dash`：去掉写字符条件里的"上游空闲"（`!S_ib[19]`） | 序列器推进的条件本来就检查 `!S_ib[19]`，总线数据选择也是清屏优先；重复的保险 |
| `mc_osd_dash`：数字右对齐的结束条件 `>= 5`（BCD 位数）改成 `>= 4` 或 `>= 6` | 少 / 多等一个时钟：移位条件是独立的 `< 5`，总移位次数不变 |
| `mc_fat_dir`：不再检查目录项属性 0x0F（长文件名项）/ 首字节 0xE5（已删除） | 这两种目录项的第一个字节不可能是数字，名字解析本来就拒绝了；重复的保险 |
| `mc_fat32`（外壳）：读取器 1 的"总线忙"接成 0 号口的 | 读取器自己的状态机在上一次读完之前不会发新命令，"忙"只是重复的保险 |
| `mc_fat32` / `mc_audio`：读取器 1 的字节序号接成 0 号口的 | 仲裁器的 `O_idx0` 和 `O_idx1` 本来就是同一根线 |
| `mc_audio`：I2S 发送器的 `I_valid` 接常数 1 | 混音器的 `O_valid` 复位后恒为 1（缺数据时补静音）；重复的保险 |
| `mc_wav_player`：重新打开（循环 / 新的播放命令）前 `P_STOPPING` 不清空环形缓冲 | `P_START` 还会再清一次，对外不可见 |
| `mc_sd_arb`：`S_free` 去掉 `~O_start`；`O_valid1` 去掉 `S_act`；发出命令那一拍丢掉"同一拍又来的新请求"；`else if (S_free)` 改成 `if (S_free)` | 都是重复的保险或用不到的情况（见 `audio.md` §8 的协议级测试 `tb_sdarb_proto`） |
| 顶层 `mctop.v`：行为层的 `I_audio_ready` 接 1 | `tb_top` 里喂食总发生在音频准备好之后；"没准备好就等着"由 `tb_behavior` 覆盖 |
| 顶层 `mctop.v`：行为层的 `I_sfx_state` 接 0 | 只用来判断"狗叫是不是正常播完"，而顶层的 `I_bark` 现在接 0（UWB 还没做）；由 `tb_behavior` 覆盖。**接上 UWB 以后要在 `tb_top` 里补一个狗叫循环的用例** |

另外，`tb_top` 为了跑得快用 `defparam` 把尾巴的 `HOME_MS` / `LEG_MS` / `GAP_MS` / `INIT_DELAY_MS`、按键 / 霍尔的去抖时间压缩了，所以**顶层把这几个参数接没接上**在 `tb_top` 里看不出来（它们的作用由 `tb_tail` / `tb_key` / `tb_hall` 用真实的写法覆盖）。改 `mctop.v` 里的 `TAIL_*` 参数时自己核对一下例化处。


## 8. 已知限制 / 上板要验证的

- **尾巴回零**：回零命令和设零点命令的字节按手册第 5 章逐字节核对过；"回零走完"是**定时**的（等 `TAIL_HOME_MS` 2 秒），不读驱动器的回零完成应答（串口只发不收）。驱动器的回零转速改得很慢（菜单 `0_Vel`）的话要把 `TAIL_HOME_MS` 加大。
- 摇摆也是**定时**的（每段等 `TAIL_LEG_MS`），不等驱动器"到位"应答。换电机 / 加减速后要重新估算这个时间。
- 驱动器上电比 FPGA 晚超过 1 秒（`TAIL_INIT_MS`）的话，回零命令发出去时它还没准备好：先给驱动器上电，或者上电后 SW1 按住 2 秒整机复位再回零一次。
- SW1 按住 2 秒整机复位，状态机里不要用"SW1 按住超过 2 秒"表示别的操作。
- 文字区的 RAM 在 100 MHz 域写、像素时钟读，没有握手：某个字符恰好在被写的那一刻被读到，那一帧会显示旧值/乱码，下一帧恢复。
