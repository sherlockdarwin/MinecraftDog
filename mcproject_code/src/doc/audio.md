# 音频：TF 卡 WAV → ES8388 → 喇叭口（背景音乐 + 音效，两路同时播）

状态：RTL 全部有测试台并仿真通过（§8）；**没有上板**。真实 TF 卡的兼容性、ES8388 模拟输出、功放、爆音、重采样的音质只能上板确认。

## 1. 三段音频怎么分工

| 文件 | 用途 | 谁触发 | 播几遍 |
| --- | --- | --- | --- |
| `1.wav` | 背景音乐 | 上电后 TF 卡和 ES8388 都准备好就**自动开始**（没有开关） | 无限循环 |
| `2.wav` | 进食音效 | 霍尔传感器 = 1（`app/mc_behavior.v`） | 每次磁铁靠近播一遍；播放中不会被重复触发，磁铁不拿开也不重播 |
| `3.wav` | 狗叫 | **以后** UWB 检测不到 / 太远时给 `mc_behavior` 的 `I_bark`；现在 `I_bark` 接 0，没人触发 | 条件一直成立就循环叫 |

**两个喇叭口分开放**：ES8388 的左、右声道是两个独立的 DAC，分别经功放到 J12（左）和 J11（右）。**J12 = 背景音乐，J11 = 音效**，各响各的（**两个口各接一个喇叭**），音效不打断背景音乐，音效放完背景音乐也不用"恢复"（它一直在放）。要做到这点必须同时读两个文件，所以有两个读文件模块共用一份挂载 + 目录表（`mc_fat32`）和一个 SD 控制器，由 `mc_sd_arb` 轮流给。

## 2. 架构和文件（`src/rtl/audio/`）

```
                                    ┌ 读文件 #0 ─ mc_wav_player #0 ─┐（背景音乐：1.wav，循环）
 TF 卡 ─ mc_sd_spi ─ mc_sd_arb ─ mc_fat32                          ├─ mc_audio_mix ─ mc_i2s_tx ─► ES8388 ─► J12 左 / J11 右 / 耳机口 J3
 (SPI)   读扇区      轮流给      │（挂载 + 目录表 一份）            │                                 ▲ I2C 配置：mc_es8388_cfg + mc_i2c_wr
                                    └ 读文件 #1 ─ mc_wav_player #1 ─┘（音效：一次一遍）
```
全部在 100 MHz 时钟域（MCLK 也是它分出来的），没有跨时钟域。`mc_audio.v` 把它们连成一个模块，顶层只例化它。

| 文件 | 作用 |
| --- | --- |
| `mc_audio.v` | 顶层封装：命令口 + 状态口 + 引脚；背景音乐的"准备好就自动播"逻辑 |
| `mc_sd_arb.v` | 两路读文件共用一个 SD 控制器：一次读扇区不被打断；两边同时要就轮流（谁刚用过谁排后面）；请求会被记住（每方挂 1 个）；数据 / done / err 只送给提出这次请求的那一方 |
| `mc_wav_player.v` | WAV 播放器：向读文件模块要文件字节 → 解析 RIFF / fmt / data（其他块跳过）→ 一帧一帧交给混音器；2 KB 环形缓冲；错误码 |
| `mc_audio_mix.v` | 两路各自重采样到 I2S 帧率（§6）+ 背景音乐放左声道、音效放右声道（立体声文件先左右取平均） |
| `mc_fat32.v` | 最小 FAT32 读取器的外壳：一个 `mc_fat_dir` + 两个 `mc_fat_rd`。挂载期间 0 号读扇区口给 `mc_fat_dir`，挂载完成后归 0 路读文件 |
| `mc_fat_dir.v` | 挂载（带 / 不带 MBR）+ 扫描根目录找 `数字.WAV` + 目录表（编号 → 文件大小和起始簇，64 项，每路读文件各读一份内容相同的 RAM，不用排队）。**两路共用，上电只扫一遍** |
| `mc_fat_rd.v` | 读一个文件：按目录表找到起始簇，沿 FAT 簇链一个扇区一个扇区地读，把文件内容一个字节一个字节地送出；缓冲没空位就等；可以中途关闭。背景音乐、音效各一个 |
| `mc_sd_spi.v` | TF 卡 SPI 模式：上电初始化（区分 V1 / V2、SDSC / SDHC）+ 读 512 字节扇区。初始化 390 kHz，之后 12.5 MHz |
| `mc_i2s_tx.v` | I2S 发送 + MCLK / SCLK / LRCK：MCLK = 100 MHz ÷ 8 = 12.5 MHz；LRCK 固定 ÷ 256 = **48828.125 Hz**（比值不变，换曲目不会出杂音） |
| `mc_es8388_cfg.v` + `mc_i2c_wr.v` | 上电后把 ES8388 配成"I2S 从模式、16 位、DAC 播放"（§7）。I2C 地址 0x11，100 kHz |

## 3. 接线和板上资源

**ES8388**（板载，不用接线；引脚已写进 `mc_pin.adc`）：

| 信号 | FPGA 脚 | 说明 |
| --- | --- | --- |
| `O_aud_mclk` | F14 | MCLK 12.5 MHz（原理图上 12.288 MHz 晶振 X4 标 NC，MCLK 由 FPGA 经 `R185` 给，和厂商例程一样） |
| `O_aud_sclk` / `O_aud_lrck` / `O_aud_dsdin` | K13 / C13 / J13 | I2S 位时钟 / 左右声道时钟 / FPGA → DAC 数据 |
| `O_aud_cclk` / `IO_aud_cdata` | A13 / B14 | I2C SCL / SDA（板上有上拉）。CE（A12）板上上拉 → 地址 0x11，**不要驱动**它 |
| `O_spk_ctl` | K15 | 喇叭功放使能（高有效，这里恒为 1） |

**喇叭口怎么接**（读底板原理图 P05_AUDIO 页；硬件手册写"扬声器接口为 NC 状态"，我理解成出厂没接喇叭）：

- ES8388 的 LOUT2 / ROUT2 各进一颗 **TT8642 单声道 D 类功放**（`U41` / `U40`，EN 脚接 `SPK_CTL_H`），输出到两个 **2 针排针：`J12` = 左声道、`J11` = 右声道**，间距 2.54 mm。
- **一个喇叭 = 两根线，接在同一个口的两个针上。** 两个口各接一个喇叭 = 背景音乐和音效分开放。
- 功放是 BTL 差分输出：**喇叭的两根线都不能接地**（接地会没声音甚至损坏功放）。
- 硬件参数图上圈出的 L22 / L23 / L25 / L26 **不是引脚，是功放输出端的磁珠**（L22/L23 属于 U41 → J12，L25/L26 属于 U40 → J11）。
- 如果板子上 J11 / J12 没焊排针，直接把喇叭线焊到焊盘上。TT8642 的功率没查到数据手册：先用 4~8 Ω 小喇叭。音量已经开到最大（`AUD_SPK_VOL = 33`，+4.5 dB）：响度够、但音乐本身很响（接近满幅）时可能破音，破音就把它改回 30（0 dB）。
- 耳机口 `J3` 直接出声，不需要功放（和喇叭口同一路信号：背景音乐在左耳、音效在右耳）。

**TF 卡座**（SPI 模式用 4 根线，3.3 V）：`O_sd_cs_n` E5（DAT3）、`O_sd_sck` D9（CLK）、`O_sd_mosi` C9（CMD）、`I_sd_miso` E6（DAT0）；E7 D5 D8 不用。

## 4. TF 卡和 WAV 文件

| 项 | 内容 |
| --- | --- |
| 放在哪 | **TF 卡根目录**（不要放子文件夹） |
| 文件名 | 数字 + `.wav`：`1.wav` … `64.wav`（`01.wav` 也算第 1 个）。其他名字被忽略。最多 64 个（`mc_fat_dir.v` / `mc_fat_rd.v` 里的 `N_CLIPS`） |
| 卡的格式 | **FAT32**（≤ 32 GB 的卡出厂默认就是；64 GB 以上默认 exFAT，不支持，要格式化成 FAT32）。带不带分区表都行 |
| WAV 格式 | **16 位 PCM**，单声道或立体声，采样率 **8000 ~ 48828 Hz**（超出会报"格式不支持"）。背景音乐**强烈建议 48 kHz**（§6）；音效、狗叫随便（16 kHz 单声道就够） |
| 传文件 | 断电 → TF 卡插读卡器 → 拷进根目录 → 弹出 → 插进板子 → 上电。**不支持热插拔**：插好卡再上电（或 SW1 按住 2 秒整机复位） |
| 格式转换 | 背景音乐：`ffmpeg -i 输入.mp3 -ar 48000 -ac 2 -c:a pcm_s16le 1.wav`；进食音效 / 狗叫：`ffmpeg -i 输入.mp3 -ar 16000 -ac 1 -c:a pcm_s16le 2.wav`（改文件名 3.wav 同理）。Audacity：导出 → WAV → "Signed 16-bit PCM" |
| 实际速度 | I2S 帧率是 48828.125 Hz，比标准 48 kHz 高 1.7 %：48 kHz 的文件实际快 1.7 %（听不出来）；其他采样率按精确比例重采样，速度准确 |

## 5. 怎么用

**没有按键操作**（2026-10-05 删掉了台架的音频页：规则已经定好，不用在板上调）：背景音乐上电自动循环，进食音效由霍尔触发，狗叫以后由 UWB 触发。

屏幕中间状态带第 1 行显示音频状态：`SD`（INIT / READY / NO SD / NO FAT）、`CODEC`（INIT / OK / ERR）、`BGM` / `SFX`（IDLE / OPEN / PLAY / ERR）。

**`mc_audio` 的端口**（Verilog 里没有"函数调用"：给输入端口一个命令，读输出端口）：

| 端口 | 方向 | 含义 |
| --- | --- | --- |
| `I_sfx_play` + `I_sfx_clip[6:0]` | 入 | 单周期脉冲：播 `<I_sfx_clip>.wav` 一遍。**音效正在播时收到的播放命令被忽略**（不重复触发、不打断） |
| `O_ready` | 出 | TF 卡已挂载 + ES8388 已配置好 |
| `O_sd_state` / `O_codec_state` / `O_nclips` | 出 | TF 卡 0 初始化中 1 就绪 2 没卡 3 不是 FAT32；ES8388 0 配置中 1 正常 2 I2C 无应答；找到几个 N.wav |
| `O_bgm_state` / `O_sfx_state` | 出 | 0 空闲 1 打开中 2 播放中 3 出错 |
| `O_bgm_err` / `O_sfx_err` | 出 | 1 没有这个编号的文件 2 不是 WAV 3 格式不支持（含采样率 > 48828 Hz） 4 读卡错误 5 TF 卡没准备好 |
| `O_sfx_busy` / `O_sfx_cur` | 出 | 音效正在打开 / 播放；正在播的曲目号 |
| `O_bgm_ur` / `O_sfx_ur` | 出 | 这一路数据没跟上的次数（上板应一直是 0） |

`mctop.v` 配置区：`AUD_BGM_CLIP`（1）、`AUD_EAT_CLIP`（2）、`AUD_BARK_CLIP`（3）、音量 `AUD_HP_VOL`（耳机）/ `AUD_SPK_VOL`（喇叭），0~33，30 = 0 dB，每级 1.5 dB，**两个都是 33（最大）**——音量是上电时写进 ES8388 的一个寄存器值，开多大都不占逻辑资源。背景音乐在左（J12）、音效在右（J11）是固定的，没有混合 / 衰减选项。

**没有屏幕时怎么知道音频好了：** 听。上电后（TF 卡初始化 + ES8388 配置，通常 1 秒左右，卡慢的话几秒）J12 / 左耳应该开始放 1.wav，到头自动再放。没声音就按 §9 排查；LED 不显示音频状态。

## 6. 重采样和混音（`mc_audio_mix.v`）

- LRCK 固定 48828.125 Hz。每一路按"自己的采样率 ÷ 48828.125"决定每个 I2S 帧要不要取新的一帧，不取就重复上一帧（**零阶保持**）。相位累加器的单位是 1/8 Hz，整数运算。
- **≥ 47.5 kHz 一律当原生 48 kHz**：每帧取一次，不重采样，音质最好。其他采样率（44.1 / 32 / 24 / 16 / 12 / 8 kHz）速度准确，但高频有点"毛"（零阶保持的镜像）。所以**背景音乐转成 48 kHz**，音效随便。想再好一点可以改线性插值（以后的事）。
- 一路刚开始播的那个 I2S 帧就取第一个采样（和上一个文件的采样率无关）；播放器没准备好（欠载）这一帧这一路补静音并给 `O_ur` 一个脉冲；不在播的那一路送静音。
- 左声道 = 背景音乐，右声道 = 音效；立体声文件先左右取平均（`(L + R) >> 1`）变成单声道。
- 背景音乐循环：文件播完立刻重新打开，衔接处有一个很短的停顿（毫秒级）。
- WAV 头解析：`RIFF` → 总长（跳过）→ `WAVE` → 依次读块：`fmt ` 取格式（必须 PCM、16 位、声道 1 或 2、采样率 8000~48828）；`data` 开始播放，长度以 data 块为准；其他块（`LIST`、`fact`）整块跳过。缓冲 2 KB，`mc_fat_rd` 有 ≥ 512 字节空位才读下一个扇区。

## 7. ES8388 配置顺序（`mc_es8388_cfg.v`）

| # | 寄存器 = 值 | 意义 |
| --- | --- | --- |
| 0 | R0 = 0x80 | 软复位 |
| 1 | R0 = 0x00，等 20 ms | 复位结束 |
| 2~3 | R1 = 0x58 → 0x50 | 模拟电源先低功耗上电，再整体打开 |
| 4~5 | R2 = 0xF3 → 0x00 | 数字部分先复位着，再放开 |
| 6 | R3 = 0xFF | ADC 全部断电（只播放） |
| 7 | R0 = 0x06 | 使能参考，VMID 500 kΩ 分压 |
| 8 | R4 = 0x3C | 左右 DAC 上电，LOUT1/ROUT1/LOUT2/ROUT2 全部使能 |
| 9 | R8 = 0x00 | 从模式，MCLK 不分频 |
| 10 | R23 = 0x18 | DAC：I2S 格式，16 位 |
| 11 | R24 = 0x02 | DAC：单倍速，比值 256 |
| 12~13 | R26 / R27 = 0x00 | 左右 DAC 数字音量 0 dB |
| 14~15 | R39 / R42 = 0x90 | 左右混频器：只放 DAC |
| 16 | R43 = 0x80 | DAC 与 ADC 共用 LRCK |
| 17~18 | R46 / R47 = `HP_VOL` | 耳机左右音量 |
| 19~20 | R48 / R49 = `SPK_VOL` | 喇叭左右音量（经板上功放） |

顺序和数值取自厂商例程 `09_aud8388_loop`，寄存器含义对过 ES8388 数据手册。

| `tb_sdarb_proto` | 仲裁器接口约定（协议级，脚本化的 SD 卡一侧）：数据 / done / err 只给主人且同拍、`O_busy` 精确、`O_start` 一拍宽且 SD 不忙时才发、同一拍两方请求的先后（两个方向）、传输中来的请求被记住、两方连续抢严格交替、读出错只有主人收到 err 且仲裁器恢复、传输中复位挂起的请求清掉 |
| `tb_audio_mix` | 混音器：两路空闲静音、一路先开始另一路中途加入、48 kHz 每帧恰好取一次、16 / 44.1 / 12 kHz 取样个数和用掉的帧数精确、**47500 Hz 起当作原生 48 kHz 的边界（47500 / 47499）**、**8000 / 4000 Hz 相位累加恰好等于一帧的那一帧（每 3125 帧一次）**、左 = 背景音乐、右 = 音效（含正负极值）、欠载补静音 + `O_ur`（**两路各测**）、"打开中"碰上帧节拍不算在播；参考模型在测试台里独立写了一遍，逐帧核对输出 |
| `tb_audio` | 错误 1 / 2 / 3（不存在 / 头不对 / 96 kHz）且不影响背景音乐、之后还能正常播；LRCK 周期；**白盒接线核对**：挂载 + 目录表、两路读文件、仲裁器、SD 控制器、播放器、混音器、I2S 之间每根线是否各接各的（比如音效那一路的"缓冲有空位"是不是接自己的播放器：背景音乐文件很短时它恒为 1，功能测试看不出来；两路各读自己的目录表读口；所有连线**每个时钟**都核对，一次性的单周期脉冲——打开 / 关闭 / 曲目号 / 读扇区命令 / 打开失败 / 文件结束 / 取走一帧 / 帧节拍——也不会漏；仿真里 SD 卡从不出错，两个口的"读错误"一直是 0，接反看不出来，所以另外用 `force` 把仲裁器两个口的读错误强制成不同的值，核对目录模块 / 两路读文件模块各收到自己那一路的；混音器给两个播放器的"欠载"标志同理：两路都在播的时候各来一个时钟，核对各播放器的欠载计数只数自己那一路；复位一松开就开始核对，所以"SD 就绪 / 已挂载"这类接常数的错在 0 时刻就被抓到） |
| `tb_top` | 顶层接线：音量参数 = 33；背景音乐上电自动开始，**第一个采样 = 1.wav 第 0 个采样**，右声道没触发时静音；喂食（霍尔 = 1）播的是 2 号、一次一遍（第一个采样核对）；行为层 → 音频的命令线每个时钟白盒核对；SW1 按住 2 秒复位后背景音乐自己再开始 |

**仿真不了的**：真实 TF 卡的兼容性（有的卡初始化慢、SPI 速度上限不同）、ES8388 的模拟输出和板上功放、上电爆音、喇叭是否破音、重采样（零阶保持）的音质。
**测试没覆盖的**：采样率低于 8 kHz 的文件（播放器的下限判断；上限用 96 kHz 的 8.wav 测了）；上电时磁铁就在旁边、而音频还没准备好的情况（`mc_behavior` 会等到准备好再播，这条逻辑有单元测试，顶层没单独测）；音频子系统里真实发生的**欠载**（仿真里数据总跟得上，欠载标志的接线靠 `force` 核对，欠载本身的计数靠 `tb_audio_mix` 的补静音 + `O_ur` 覆盖）。

## 9. 排错

| 现象 | 先怀疑 | 怎么查 |
| --- | --- | --- |
| `CODEC ERR` | ES8388 的 I2C 没应答 | `A13` / `B14` 是否接对、板上 R191 / R172 是否在；ChipWatcher 抓 `O_aud_cclk` / `IO_aud_cdata` |
| `CODEC OK`、`BGM PLAY` 但没声音 | 功放没使能 / 喇叭线接法 | `O_spk_ctl`（K15）是否为高；喇叭两根线接在 J11 或 J12 的两个针上、不接地；先接耳机口听 |
| 有声音，但噪声大 / 音调不对 | MCLK 太差 / 比值 | 示波器看 F14 是否 12.5 MHz、K13（3.125 MHz）和 C13（48.8 kHz）是否稳定 |
| 背景音乐不响，别的都正常 | TF 卡 / 文件 | `SD` 是不是 READY、`BGM` 是不是 ERR；根目录有没有 `1.wav` |
| `SD NO SD` | 没插卡 / 卡座接触 / SPI 脚 | 插好卡后 SW1 按住 2 秒复位；E5 / D9 / C9 / E6 是否对；换卡（有的卡对 SPI 模式支持差） |
| `SD NO FAT` | 卡不是 FAT32 | 重新格式化成 FAT32 |
| `SD READY` 但 `BGM ERR` | 文件名不对 / 不在根目录 / 格式不对 | 必须是 `1.wav` 这样的数字名；Windows"隐藏已知文件类型"开着时别写成 `1.wav.wav` |
| 声音断续 | 卡太慢 | 换 Class 10 的卡；把 `mc_sd_spi.v` 的 `FAST_DIV` 改小（4 → 3 提到 16.7 MHz，不稳就改回） |
| 背景音乐有点"毛" | 不是 48 kHz | 转成 48 kHz（§4） |
